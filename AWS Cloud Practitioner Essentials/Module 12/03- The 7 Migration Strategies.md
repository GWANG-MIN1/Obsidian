# AWS 마이그레이션의 7R 전략 (The 7 Rs of Migration)

## 7R 마이그레이션 전략이란?

AWS는 기존 애플리케이션을 클라우드로 이전할 때 **애플리케이션의 특성과 비즈니스 요구사항에 맞는 7가지 마이그레이션 전략(7R)** 을 제시한다.

각 애플리케이션은 상황에 따라 서로 다른 전략을 적용할 수 있으며, 모든 애플리케이션이 동일한 방식으로 마이그레이션되는 것은 아니다.

---

# AWS 7R 전략

| 전략 | 설명 |
|------|------|
| **Rehost** | 기존 애플리케이션을 거의 변경하지 않고 그대로 이전 |
| **Relocate** | VM 기반 워크로드를 클라우드 환경으로 재배치 |
| **Replatform** | 일부 최적화를 수행하지만 핵심 코드는 변경하지 않음 |
| **Refactor / Re-architect** | 애플리케이션을 클라우드 환경에 맞게 재설계 |
| **Repurchase** | 기존 소프트웨어를 새로운 SaaS 또는 다른 제품으로 교체 |
| **Retain** | 현재 환경에 그대로 유지 |
| **Retire** | 더 이상 필요 없는 애플리케이션을 제거 |

---

# 1. Rehost (리호스팅, Lift and Shift)

가장 단순한 마이그레이션 전략이다.

기존 애플리케이션을 **거의 변경하지 않고 AWS로 그대로 이전**한다.

일반적으로 **Lift and Shift** 방식이라고 한다.

### 특징

- 코드 수정 없음
- 애플리케이션 구조 변경 없음
- 빠른 마이그레이션
- 구현이 가장 쉬움

### 장점

- 마이그레이션 속도가 빠름
- 위험이 적음
- 초기 비용이 낮음

### 예시

기존 온프레미스 서버를 **Amazon EC2**로 그대로 이전

> 리호스팅만으로도 **총소유비용(TCO)을 최대 약 30% 절감**할 수 있는 경우가 있다.

---

# 2. Relocate (재배치)

가상 머신(VM) 기반 워크로드의 **호스팅 위치만 AWS로 변경**하는 전략이다.

애플리케이션 자체는 거의 변경하지 않는다.

### 특징

- VM 기반 환경 이전
- VMware 등의 워크로드 이전
- 인프라 위치만 변경

### 예시

온프레미스 VMware 환경을 **VMware Cloud on AWS**로 이전

---

# 3. Replatform (리플랫포밍, Lift, Tinker and Shift)

Rehost와 유사하지만, **클라우드 환경에 맞게 일부 최적화**를 수행한다.

핵심 비즈니스 로직은 변경하지 않으며, 새로운 애플리케이션을 개발하지도 않는다.

### 특징

- 일부 클라우드 최적화
- 핵심 코드 수정 없음
- 새로운 코드 개발 없음
- 성능 및 운영 효율 향상

### 예시

애플리케이션은 그대로 유지하면서 데이터베이스를 **Amazon RDS**로 이전

---

# 4. Refactor / Re-architect (리팩터링 / 리아키텍팅)

애플리케이션을 **클라우드 환경에 맞게 새롭게 설계**하는 전략이다.

새로운 기능을 추가하거나 성능을 크게 개선해야 하는 경우 사용한다.

### 특징

- 새로운 코드 작성
- 애플리케이션 구조 재설계
- 클라우드 네이티브 환경 활용
- 가장 많은 개발 작업 필요

### 장점

- 확장성 향상
- 성능 향상
- 운영 효율성 향상
- AWS 서비스 적극 활용

### 단점

- 초기 비용이 가장 큼
- 개발 기간이 길어질 수 있음

---

# 5. Repurchase (재구매, Drop and Shop)

기존 소프트웨어를 버리고 **새로운 제품이나 SaaS 서비스로 교체**하는 전략이다.

### 특징

- 새로운 소프트웨어 구매
- 기존 라이선스 종료
- SaaS 전환

### 예시

- 자체 CRM → Salesforce
- 자체 이메일 서버 → Amazon WorkMail 또는 Microsoft 365

### 장점

- 최신 기능 활용
- 운영 부담 감소

### 단점

- 초기 비용 증가 가능
- 시스템 변경 및 사용자 교육 필요

---

# 6. Retain (유지)

현재 애플리케이션을 **당분간 기존 환경에 그대로 유지**하는 전략이다.

즉시 마이그레이션할 필요가 없거나 비즈니스 타당성이 부족한 경우 선택한다.

### 특징

- 변경 없음
- 기존 환경 유지
- 추후 마이그레이션 가능

### 예시

곧 사용이 종료될 예정인 애플리케이션을 기존 환경에 그대로 유지

---

# 7. Retire (사용 중지)

더 이상 필요하지 않은 애플리케이션을 제거하는 전략이다.

기업에서는 엔터프라이즈 워크로드 중 **10% 이상이 실제로 사용되지 않는 경우도 흔하다.**

### 장점

- 운영 비용 절감
- 라이선스 비용 절감
- 관리 부담 감소
- 불필요한 리소스 제거

### 예시

사용하지 않는 레거시 시스템 종료

---

# AWS 7R 전략 비교

| 전략 | 코드 변경 | 난이도 | 대표 특징 |
|------|-----------|--------|-----------|
| **Rehost** | 없음 | ★ | Lift and Shift, 가장 빠른 이전 |
| **Relocate** | 없음 | ★ | VM 기반 워크로드의 위치만 변경 |
| **Replatform** | 최소 | ★★ | 일부 최적화, 핵심 코드는 유지 |
| **Refactor** | 많음 | ★★★★★ | 클라우드 네이티브로 재설계 |
| **Repurchase** | 새 제품 사용 | ★★★ | 기존 소프트웨어를 SaaS 등으로 교체 |
| **Retain** | 없음 | ★ | 현재 환경 유지 |
| **Retire** | 제거 | ★ | 더 이상 사용하지 않는 시스템 종료 |

---

# 핵심 정리

- AWS는 클라우드 마이그레이션을 위해 **7R(Migration Strategies)** 을 제시한다.
- **Rehost**는 **Lift and Shift** 방식으로, 코드를 수정하지 않고 애플리케이션을 그대로 AWS로 이전하는 전략이다.
- **Relocate**는 **VM 기반 워크로드의 호스팅 위치만 AWS로 변경**하는 전략이다.
- **Replatform**은 일부 클라우드 최적화를 수행하지만 **핵심 코드 수정이나 새로운 코드 개발은 하지 않는다.**
- **Refactor(Re-architect)** 는 새로운 코드를 작성하여 애플리케이션을 클라우드 네이티브 환경에 맞게 재설계하는 전략이다.
- **Repurchase**는 기존 소프트웨어를 새로운 SaaS 또는 다른 제품으로 교체하는 전략이다.
- **Retain**은 현재 환경을 그대로 유지하고, **Retire**는 더 이상 필요 없는 애플리케이션을 제거하여 비용과 운영 부담을 줄이는 전략이다.

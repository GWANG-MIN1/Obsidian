# AWS 데이터베이스 마이그레이션 (Database Migration)

## 데이터베이스 마이그레이션이란?

데이터베이스 마이그레이션(Database Migration)은 기존 데이터베이스를 AWS 클라우드 환경으로 이전하거나, 다른 데이터베이스 엔진으로 변경하는 과정이다.

기업은 다음과 같은 이유로 데이터베이스를 AWS로 마이그레이션한다.

- 비용 최적화
- 성능 향상
- 확장성 확보
- 운영 효율성 향상
- 레거시 시스템 현대화(Modernization)

AWS는 이를 지원하기 위해 다음 두 가지 핵심 서비스를 제공한다.

- **AWS Database Migration Service (AWS DMS)**
- **AWS Schema Conversion Tool (AWS SCT)**

---

# 1. AWS Database Migration Service (AWS DMS)

## AWS DMS란?

**AWS Database Migration Service(AWS DMS)** 는 데이터베이스를 AWS로 쉽고 안전하게 이전할 수 있도록 지원하는 서비스이다.

관계형 데이터베이스(Relational Database)뿐만 아니라 NoSQL 데이터베이스도 마이그레이션할 수 있다.

쉽게 말하면,

> **데이터를 원본 데이터베이스에서 대상 데이터베이스로 안전하게 복제하고 이전해 주는 서비스**이다.

---

# AWS DMS 동작 방식

AWS DMS는 **복제(Replication) 소프트웨어가 실행되는 관리형 복제 인스턴스(가상 머신)** 를 사용한다.

사용자는 다음 정보를 설정하면 된다.

- **원본(Source) 데이터베이스**
- **대상(Target) 데이터베이스**

이후 DMS가 데이터를 자동으로 복제하고 전송한다.

```
원본 데이터베이스
        │
        ▼
AWS DMS (복제 인스턴스)
        │
        ▼
대상 데이터베이스
```

---

# AWS DMS의 주요 기능

### 다양한 데이터베이스 지원

- 관계형 데이터베이스(RDBMS)
- NoSQL 데이터베이스
- 데이터 웨어하우스 등

---

### 최소한의 다운타임

원본 데이터베이스가 계속 운영되는 상태에서도 데이터를 복제할 수 있다.

즉, 서비스 중단 시간을 최소화하면서 마이그레이션을 수행할 수 있다.

---

### 지속적인 데이터 복제

초기 데이터 이전 후에도 변경된 데이터를 계속 복제하여 원본과 대상 데이터베이스를 동기화할 수 있다.

---

### 다양한 마이그레이션 지원

- 온프레미스 → AWS
- AWS 리전 간 마이그레이션
- 가용 영역(AZ) 간 마이그레이션
- AWS 계정 간 마이그레이션

---

# 데이터베이스 엔진 변경 (이기종 마이그레이션)

기존 데이터베이스 엔진을 다른 엔진으로 변경하는 것도 가능하다.

예시

- Oracle → Amazon Aurora PostgreSQL
- Microsoft SQL Server → PostgreSQL
- MySQL → Amazon Aurora

이처럼 **서로 다른 데이터베이스 엔진 간의 마이그레이션**을 **이기종(Heterogeneous) 마이그레이션**이라고 한다.

---

# 2. AWS Schema Conversion Tool (AWS SCT)

## AWS SCT란?

**AWS Schema Conversion Tool(AWS SCT)** 은 기존 데이터베이스의 **스키마(Schema)와 데이터베이스 코드(SQL, 저장 프로시저 등)** 를 대상 데이터베이스 엔진과 호환되는 형식으로 변환하는 도구이다.

쉽게 말하면,

> **데이터 자체가 아니라 데이터베이스 구조와 코드를 새로운 데이터베이스에서 사용할 수 있도록 변환하는 도구**이다.

---

# 왜 SCT가 필요한가?

서로 다른 데이터베이스는 구조와 문법이 다르기 때문에 단순히 데이터를 복사해서는 사용할 수 없다.

예를 들어

- Oracle
- SQL Server
- PostgreSQL
- MySQL

은 각각 스키마 구조와 SQL 문법이 다를 수 있다.

SCT는 이러한 차이를 분석하여 자동으로 변환하고, 자동 변환이 어려운 부분은 수동으로 수정할 수 있도록 알려준다.

---

# AWS SCT의 주요 기능

- 데이터베이스 스키마 변환
- SQL 코드 변환
- 저장 프로시저 변환
- 함수(Function) 변환
- 자동 변환 지원
- 수동 수정이 필요한 항목 표시

---

# AWS DMS와 AWS SCT의 차이

| 서비스 | 역할 |
|---------|------|
| **AWS DMS** | 데이터를 원본 데이터베이스에서 대상 데이터베이스로 복제 및 이전 |
| **AWS SCT** | 데이터베이스 스키마와 코드를 대상 데이터베이스 형식으로 변환 |

> **정리하면, DMS는 '데이터를 옮기는 역할', SCT는 '데이터베이스 구조와 코드를 변환하는 역할'을 한다.**

---

# AWS DMS + AWS SCT 사용 흐름

```
기존 데이터베이스

        │

        ▼

AWS SCT
(스키마 및 코드 변환)

        │

        ▼

새로운 데이터베이스 생성

        │

        ▼

AWS DMS
(데이터 복제 및 이전)

        │

        ▼

AWS 데이터베이스 운영
```

---

# AWS DMS와 SCT의 장점

### 시간 절약

수작업으로 몇 달이 걸릴 수 있는 마이그레이션 작업을 자동화하여 빠르게 수행할 수 있다.

---

### 비용 절감

자동화된 변환과 데이터 이전을 통해 개발 및 운영 비용을 줄일 수 있다.

---

### 유연성

기업의 요구사항에 맞는 다양한 데이터베이스 엔진으로 이전할 수 있다.

---

### 보안

데이터를 안전하게 이전하고 AWS의 보안 기능을 활용할 수 있다.

---

# 핵심 정리

- 기업은 **비용 최적화, 성능 향상, 현대화** 등을 위해 데이터베이스를 AWS로 마이그레이션한다.
- **AWS Database Migration Service(AWS DMS)** 는 관계형 데이터베이스와 NoSQL 데이터베이스를 AWS로 이전하는 서비스이며, **복제 인스턴스(가상 머신)** 를 사용하여 데이터를 복제하고 전송한다.
- DMS는 **원본 데이터베이스가 계속 운영되는 상태에서도(최소 다운타임)** 데이터를 복제할 수 있으며, **리전 간 또는 가용 영역(AZ) 간 마이그레이션**도 지원한다.
- 서로 다른 데이터베이스 엔진으로 이전하는 **이기종(Heterogeneous) 마이그레이션**에서는 **AWS Schema Conversion Tool(AWS SCT)** 을 함께 사용한다.
- **AWS SCT**는 **소스 데이터베이스의 스키마와 코드를 대상 데이터베이스와 호환되는 형식으로 변환**하여 마이그레이션을 준비한다.
- **DMS는 데이터를 이전하고, SCT는 스키마와 코드를 변환**하는 역할을 수행한다.

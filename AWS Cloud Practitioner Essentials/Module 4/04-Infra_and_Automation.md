# 코드형 인프라(IaC)와 AWS CloudFormation

## 리전 간 동일한 환경 구성

- **리전 A의 리소스 구성을 리전 B에도 동일하게 배포 가능**
- 동일한 인프라를 여러 리전에 일관되게 구축

---

## 코드형 인프라(IaC, Infrastructure as Code)

- **인프라를 코드(파일)로 정의**하는 방식
- 서버, 네트워크, 데이터베이스 등의 리소스를 **자동으로 생성 및 관리**

**장점**

- 반복 작업 자동화
- 동일한 환경 재현 가능
- 인적 오류(Human Error) 감소
- 버전 관리 가능

---

## AWS CloudFormation

- AWS에서 제공하는 **선언형 IaC 서비스**
- 템플릿(YAML/JSON)에 원하는 인프라를 정의하면 AWS가 자동으로 구성

**동작 과정**

1. 템플릿 작성
2. CloudFormation이 템플릿 분석
3. 필요한 AWS 리소스 자동 프로비저닝
4. 스택(Stack) 생성 및 관리

**장점**

- 동일한 환경을 언제든 재구성 가능
- 완전 자동화된 인프라 배포
- 인적 개입 최소화
- **명령 한 번으로** 필요한 리소스를 정확하게 생성
- 장애 발생 시 동일한 아키텍처를 빠르게 복원하여 **복원력(Resilience)** 향상

---

# AWS 리소스와 상호작용하는 3가지 방법

|방법|설명|
|---|---|
|**AWS Management Console**|웹 브라우저에서 GUI를 통해 리소스를 관리|
|**프로그래밍 방식 액세스**|AWS CLI, SDK를 이용해 명령어나 코드로 리소스 제어|
|**코드형 인프라(IaC)**|CloudFormation 등으로 인프라를 코드로 정의하여 자동 배포|

---

### 한 줄 요약

- **Console** → 사람이 직접 클릭해서 관리
- **CLI / SDK** → 코드나 명령어로 제어
- **IaC (CloudFormation)** → 인프라 자체를 코드로 정의하여 자동 구축 및 관리

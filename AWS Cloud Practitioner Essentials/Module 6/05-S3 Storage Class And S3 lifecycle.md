# Amazon S3 스토리지 클래스

> **데이터의 접근 빈도와 비용에 따라 다양한 스토리지 클래스를 제공**
>
> **하나의 버킷(Bucket) 안에서도 서로 다른 스토리지 클래스를 사용할 수 있다.**

---

## 1. S3 Standard

> **자주 사용하는 데이터 저장**

### 특징
- 가장 높은 가용성
- 짧은 지연 시간
- 높은 처리량
- 여러 가용 영역(AZ)에 저장

### 사용 사례
- 웹 사이트
- 모바일 애플리케이션
- 자주 사용하는 데이터
- 콘텐츠 배포

---

## 2. S3 Standard-Infrequent Access (Standard-IA)

> **자주 사용하지 않지만 필요할 때 즉시 접근해야 하는 데이터**

### 특징
- Standard보다 저장 비용 저렴
- 즉시 검색 가능
- 여러 가용 영역(AZ)에 저장

### 사용 사례
- 백업
- 재해 복구(DR)
- 장기 보관 데이터

---

## 3. S3 One Zone-IA

> **하나의 가용 영역(AZ)에만 저장하는 저비용 스토리지**

### 특징
- 저장 비용이 가장 저렴
- 즉시 검색 가능
- 하나의 AZ에만 저장

### 단점
- 가용 영역(AZ) 장애 발생 시 데이터 손실 가능

### 사용 사례
- 쉽게 다시 생성 가능한 데이터
- 복제본 데이터
- 중요도가 낮은 백업

---

## 4. Amazon S3 Glacier

> **장기 보관(Archive)용 스토리지**

### ① Glacier Instant Retrieval
- 거의 접근하지 않는 데이터
- 즉시 검색 가능
- 장기 보관 + 빠른 조회

### ② Glacier Flexible Retrieval
- 검색 시간이 분 ~ 시간
- 백업 및 아카이브에 적합

### ③ Glacier Deep Archive
- 가장 저렴한 스토리지
- 검색 시간이 수 시간 ~ 12시간 이상
- 거의 접근하지 않는 장기 보관 데이터

---

# S3 Intelligent-Tiering

> **객체의 접근 패턴을 분석하여 스토리지 클래스를 자동으로 변경하는 서비스**

### 자동 이동
- Frequent Access
- Infrequent Access
- Archive Instant Access
- Deep Archive Access

### 장점
- 별도 관리 없이 비용 최적화
- 접근 빈도에 따라 자동 이동

---

# S3 Lifecycle

> **객체의 수명 주기를 자동으로 관리하는 기능**

### 기능
- 오래된 데이터를 다른 스토리지 클래스로 자동 이동
- 오래된 데이터 자동 삭제
- 비용 절감

### 예시
- 업로드 후 30일 → Standard-IA
- 90일 → Glacier
- 365일 → 자동 삭제

---

# S3 Storage Class Analysis

> **객체의 접근 패턴을 분석하여 적절한 스토리지 클래스로 이동할 수 있도록 지원하는 기능**

### 특징
- 접근 빈도 분석
- 비용 절감 추천
- Lifecycle 정책 수립에 활용

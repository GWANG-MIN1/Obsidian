# 트래픽 처리와 로드 밸런싱

사용자가 증가하면 하나의 서버만으로는 모든 요청을 처리하기 어렵다. 이를 해결하기 위해 **로드 밸런싱(Load Balancing)** 을 사용한다.

---

# Elastic Load Balancing (ELB)

ELB는 여러 EC2 인스턴스에 트래픽을 자동으로 분산해 주는 AWS 서비스이다.

### 주요 기능

- 여러 EC2 인스턴스로 요청 분산
- 특정 서버에 트래픽 집중 방지
- 장애가 발생한 서버를 자동 제외
- 트래픽 증가 시 확장 지원
- 트래픽 감소 시 축소 지원

---

# ELB의 장점

### 효율적인 자원 관리

- 서버 부하를 균등하게 분산
- 특정 서버 과부하 방지

### 비용 효율성

- 필요한 인스턴스만 사용
- Auto Scaling과 연동하여 비용 절감

### 높은 가용성

- 서버 한 대가 장애가 나도 서비스 지속 가능

---

# 로드 밸런싱 방식

## 1. 라운드 로빈 (Round Robin)

요청을 순서대로 서버에 분배한다.

```
사용자 요청  
↓  
서버1 → 서버2 → 서버3 → 서버1 → 서버2
```

---

## 2. 최소 연결 (Least Connections)

현재 연결 수가 가장 적은 서버로 요청을 전달한다.

```
서버1 : 30명  
서버2 : 10명  
서버3 : 15명  
  
→ 서버2로 요청 전달
```

---

## 3. IP 해시 (IP Hash)

사용자의 IP 주소를 기준으로 서버를 결정한다.

- 같은 사용자는 같은 서버로 연결될 가능성이 높음
- 세션 유지가 필요한 서비스에 사용

---

## 4. 최소 응답 시간 (Least Response Time)

응답 속도가 가장 빠른 서버로 요청을 전달한다.

- 서버 상태와 응답 시간을 함께 고려
- 사용자 체감 성능 향상

---

# 프런트엔드와 백엔드 연결

```
사용자  
↓  
프런트엔드  
↓  
ELB  
↓ ↓ ↓  
EC2 EC2 EC2
```

- ELB가 프런트엔드와 백엔드 인스턴스 사이의 연결을 관리
- 현재 부하가 적은 인스턴스로 요청 전달
- 모든 작업은 독립적인 요청(Entity)으로 처리
- 사용자는 어떤 서버가 처리하는지 알 필요가 없음

---

# Auto Scaling과 ELB

```
트래픽 증가  
↓  
CloudWatch 감지  
↓  
Auto Scaling  
↓  
EC2 인스턴스 추가  
↓  
ELB가 새로운 서버로 트래픽 분산
```

---

# 한 줄 정리

> ELB는 여러 EC2 인스턴스에 트래픽을 자동으로 분산하여 서버 과부하를 방지하고, Auto Scaling과 함께 안정성과 비용 효율성을 높여주는 서비스이다.

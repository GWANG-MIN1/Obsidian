# 느슨한 결합(Loose Coupling)과 메시지 서비스

시스템이 서로 직접 연결되어 있으면 한 서비스에 문제가 발생했을 때 다른 서비스에도 영향을 줄 수 있다. 이를 해결하기 위해 **느슨한 결합(Loose Coupling)** 구조를 사용한다.

```
A (서비스)  
↓  
Message Queue  
↓  
B (서비스)
```

- A는 작업 요청만 전달
- B는 나중에 메시지를 가져와 처리
- 두 서비스가 직접 연결되지 않음

---

# Amazon SQS (Simple Queue Service)

메시지를 저장하는 대기열(Queue) 서비스이다.

### 역할

- 메시지 전송
- 메시지 저장
- 메시지 수신
- 메시지 처리 전까지 대기

### 동작 과정

```
A 서비스  
↓  
SQS 대기열  
↓  
B 서비스
```

### 장점

- 서비스 간 의존성 감소
- 트래픽 급증 시 메시지 보관 가능
- 장애가 발생해도 데이터 손실 방지

**예시**

- 주문 접수 → 결제 처리
- 회원 가입 → 이메일 발송
- 이미지 업로드 → 이미지 변환

---

# Amazon SNS (Simple Notification Service)

메시지를 여러 구독자에게 전달하는 알림 서비스이다.

### 역할

- 메시지 발행(Publish)
- 여러 대상에게 동시에 전달(Subscribe)

### 전달 대상

- 이메일
- SMS
- 모바일 푸시 알림
- Lambda
- SQS
- HTTP 엔드포인트

---

## SNS 동작 구조

```
애플리케이션  
↓  
SNS  
↓ ↓ ↓  
이메일 SMS 모바일 알림
```

---

# SQS와 SNS 차이

|항목|SQS|SNS|
|---|---|---|
|목적|메시지 저장 및 대기|메시지 알림 및 전파|
|구조|Queue|Topic|
|처리 방식|소비자가 가져감(Pull)|구독자에게 전달(Push)|
|사용 목적|작업 처리|알림 전달|
|대표 예시|주문 처리|문자·이메일 알림|

---

# 예시

### SQS

```
주문 생성  
↓  
SQS  
↓  
결제 서버
```

### SNS

```
주문 완료  
↓  
SNS  
↓ ↓ ↓  
이메일 SMS 앱 알림
```

---

## 한 줄 정리

> SQS는 작업을 잠시 저장해 두는 메시지 대기열 서비스이고, SNS는 여러 사용자나 서비스에 알림을 전달하는 메시지 발행·구독 서비스이다.

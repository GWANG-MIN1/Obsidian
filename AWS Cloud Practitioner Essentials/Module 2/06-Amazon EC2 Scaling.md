클라우드의 대표적인 특징 중 하나는 **확장성**과 **탄력성**이다.

---

## 1. 확장성 (Scalability)

시스템의 리소스를 추가하여 증가한 워크로드를 처리할 수 있는 능력이다.

### 스케일 업 (Scale Up)

- 기존 서버의 성능을 높이는 방식
- CPU, 메모리 등을 증가시킴

**예시**

- t3.micro → t3.large

### 스케일 아웃 (Scale Out)

- 서버의 개수를 늘리는 방식
- 여러 대의 서버가 작업을 분산 처리

**예시**

- 웹 서버 1대 → 웹 서버 3대

---

## 2. 탄력성 (Elasticity)

실시간 수요 변화에 따라 리소스를 자동으로 늘리거나 줄이는 능력이다.

- 트래픽 증가 → 자동으로 서버 추가
- 트래픽 감소 → 자동으로 서버 제거

즉, **필요할 때만 자원을 사용하여 비용을 절감하는 기능**이다.

---

# Auto Scaling

Amazon EC2 인스턴스 수를 자동으로 조절하는 서비스이다.

### 스케일 아웃 (Scale Out)

- 트래픽 증가 시 인스턴스 추가

### 스케일 인 (Scale In)

- 트래픽 감소 시 인스턴스 제거

### 스케일 업 (Scale Up)

- 더 높은 성능의 인스턴스로 변경

### 스케일 다운 (Scale Down)

- 더 낮은 성능의 인스턴스로 변경

---

# Amazon CloudWatch

AWS의 모니터링 서비스이다.

**기능**

- CPU 사용률 모니터링
- 메모리 및 네트워크 상태 확인
- 로그 및 성능 지표 수집
- 경보(Alarm) 생성

CloudWatch가 시스템 상태를 감시하고, 특정 조건이 발생하면 Auto Scaling이 동작한다.

---

## 동작 과정

```
사용자 증가  
↓  
CPU 사용률 증가  
↓  
CloudWatch 감지  
↓  
Auto Scaling 실행  
↓  
EC2 인스턴스 추가 (Scale Out)
```

```
사용자 감소
      ↓
CPU 사용률 감소
      ↓
CloudWatch 감지
      ↓
Auto Scaling 실행
      ↓
EC2 인스턴스 제거 (Scale In)
```

---

## 개념 비교

|개념|의미|예시|
|---|---|---|
|확장성 (Scalability)|시스템 용량을 늘릴 수 있는 능력|서버 성능 증가, 서버 추가|
|탄력성 (Elasticity)|수요에 따라 자동으로 자원을 조절하는 능력|트래픽에 따라 자동 증감|
|Auto Scaling|EC2를 자동으로 증감시키는 기능|서버 자동 추가/제거|
|CloudWatch|시스템 상태를 모니터링하는 서비스|CPU 사용률 감시|

---

### 한 줄 정리

> 확장성은 시스템을 더 크게 만들 수 있는 능력이고, 탄력성은 필요할 때 자동으로 크기를 조절하는 능력이며, CloudWatch가 상태를 감시하고 Auto Scaling이 이를 바탕으로 EC2를 자동으로 증감시킨다.

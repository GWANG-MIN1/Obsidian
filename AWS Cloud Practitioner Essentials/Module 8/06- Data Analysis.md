# 06. 데이터 분석과 데이터 파이프라인

---

# 데이터(Data)의 중요성

데이터는 **AI, ML, 데이터 분석과 같은 첨단 기술의 핵심 자원**이다.

데이터를 수집하고 분석하면 과거의 정보를 바탕으로 **추세(Trend)** 와 **인사이트(Insight)** 를 발견하여 더 나은 의사결정을 내릴 수 있다.

> **AI와 ML은 결국 데이터의 품질과 양에 크게 의존한다.**

---

# 데이터 분석(Data Analytics)

> 원시 데이터(Raw Data)를 분석하여 의미 있는 정보와 인사이트를 찾아내는 과정

단순히 데이터를 저장하는 것이 아니라, 데이터를 활용하여 미래를 예측하고 비즈니스 의사결정을 지원한다.

### 데이터 분석의 목적

- 추세(Trend) 분석
- 패턴(Pattern) 발견
- 의사결정 지원
- 미래 예측

---

# 활용 사례

## 금융 회사

고객의 데이터를 분석하여

- 대출 가능 여부 평가
- 신용도 분석
- 맞춤형 금융 상품 추천

---

## 보험 회사

데이터 분석을 통해

- 위험(Risk) 평가
- 보험료 산정
- 보험 승인 여부 결정
- 규제 요구사항 준수

---

# AI, ML, 데이터 분석의 공통점

AI와 ML, 그리고 기존 데이터 분석은 모두 **데이터를 기반으로 동작**한다.

### 공통점

- 많은 데이터 필요
- 정확한 데이터 필요
- 지속적인 데이터 수집 필요

> **데이터가 부족하거나 품질이 낮으면 AI와 분석 결과도 부정확해진다.**

---

# 데이터는 여러 곳에 존재한다

기업의 데이터는 하나의 시스템에만 저장되지 않는다.

예를 들어,

- 데이터베이스
- 애플리케이션
- 로그 파일
- IoT 장치
- 웹사이트
- 클라우드 스토리지

등 다양한 위치에 분산되어 있다.

따라서 데이터를 한곳으로 모아 분석 가능한 형태로 만들어야 한다.

---

# ETL (Extract, Transform, Load)

> 여러 데이터 소스에서 데이터를 추출하여 변환한 후 대상 시스템에 적재하는 데이터 처리 방식

```
다양한 데이터 소스
        │
        ▼
Extract (추출)
        ▼
Transform (변환)
        ▼
Load (적재)
        ▼
데이터 웨어하우스
```

### 단계

### 1. Extract (추출)

다양한 데이터 소스에서 데이터를 가져온다.

예시

- 데이터베이스
- 로그
- 파일
- API

---

### 2. Transform (변환)

데이터를 분석하기 좋은 형태로 가공한다.

예시

- 데이터 정제
- 형식 변환
- 중복 제거
- 결측치 처리

---

### 3. Load (적재)

변환된 데이터를 데이터 웨어하우스 등의 대상 시스템에 저장한다.

---

# ELT (Extract, Load, Transform)

> 데이터를 먼저 저장한 후 필요할 때 변환하는 방식

```
다양한 데이터 소스
        │
        ▼
Extract (추출)
        ▼
Load (적재)
        ▼
Transform (변환)
```

### 특징

- 먼저 데이터를 저장
- 이후 필요한 시점에 변환
- 대용량 데이터 처리에 적합

---

# ETL vs ELT

| 구분 | ETL | ELT |
|------|-----|-----|
| 순서 | Extract → Transform → Load | Extract → Load → Transform |
| 변환 시점 | 저장 전 | 저장 후 |
| 장점 | 저장되는 데이터가 이미 정제됨 | 대용량 데이터 처리에 유리 |
| 적합한 환경 | 전통적인 데이터 웨어하우스 | 클라우드 기반 데이터 플랫폼 |

> 어떤 방식을 사용할지는 **비즈니스 요구사항과 인프라 환경**에 따라 결정된다.

---

# ETL이 필요 없는 경우

다음과 같은 경우에는 ETL 과정이 필요하지 않을 수 있다.

- 데이터가 이미 분석 가능한 형식인 경우
- 데이터가 대상 시스템에 이미 저장되어 있는 경우
- 별도의 변환 과정이 필요 없는 경우

---

# 데이터 파이프라인(Data Pipeline)

> 데이터의 수집부터 저장, 처리, 분석까지의 과정을 자동화하는 시스템

생산 공장의 **조립 라인(Assembly Line)** 처럼 데이터가 자동으로 이동하고 처리된다.

```
데이터 수집
      ↓
데이터 저장
      ↓
데이터 처리
      ↓
데이터 분석
      ↓
데이터 시각화
```

### 역할

- 데이터 자동 수집
- 데이터 이동 자동화
- 데이터 처리 자동화
- 분석 자동화

---

# AWS 데이터 파이프라인 서비스

AWS는 데이터 파이프라인의 각 단계를 담당하는 다양한 서비스를 제공한다.

## 1. 데이터 수집(Ingestion)

### Amazon Kinesis

- 실시간 데이터 수집
- 스트리밍 데이터 처리

### AWS Glue

- ETL 서비스
- 데이터 카탈로그
- 데이터 변환

---

## 2. 데이터 저장(Storage)

### Amazon S3

- 데이터 레이크(Data Lake)
- 객체 스토리지

### Amazon Redshift

- 데이터 웨어하우스(Data Warehouse)
- 대규모 분석

---

## 3. 데이터 처리(Processing)

### Amazon EMR

- Apache Spark
- Hadoop
- 대용량 데이터 처리

---

## 4. 데이터 시각화(Visualization)

### Amazon QuickSight

- 대시보드 생성
- 데이터 시각화
- BI(Business Intelligence) 분석

---

# AWS 데이터 파이프라인 예시

```
데이터 생성
      │
      ▼
Amazon Kinesis
(실시간 데이터 수집)
      │
      ▼
AWS Glue
(ETL / 데이터 변환)
      │
      ▼
Amazon S3 / Amazon Redshift
(데이터 저장)
      │
      ▼
Amazon EMR
(대규모 데이터 처리)
      │
      ▼
Amazon QuickSight
(분석 및 시각화)
```

---

# AWS 서비스 통합

AWS의 데이터 서비스는 서로 긴밀하게 통합되어 하나의 데이터 분석 플랫폼을 구성한다.

예를 들어,

- **Amazon Kinesis**가 실시간 데이터를 수집하면,
- **AWS Glue**가 데이터를 정제하고 변환한 뒤,
- **Amazon S3** 또는 **Amazon Redshift**에 저장한다.
- 이후 **Amazon EMR**이 데이터를 처리하고,
- **Amazon QuickSight**가 이를 시각화하여 분석 결과를 제공한다.

---

# 핵심 정리

- 데이터는 AI, ML, 데이터 분석의 핵심 자원이다.
- 데이터 분석은 원시 데이터를 분석하여 추세와 인사이트를 도출하는 과정이다.
- **ETL**은 데이터를 **추출 → 변환 → 적재**하는 방식이며, **ELT**는 **추출 → 적재 → 변환**하는 방식이다.
- ETL과 ELT 중 어떤 방식을 사용할지는 요구사항과 인프라 환경에 따라 달라진다.
- 데이터 파이프라인은 데이터의 수집부터 저장, 처리, 분석까지의 흐름을 자동화한다.
- AWS는 **Kinesis, Glue, S3, Redshift, EMR, QuickSight** 등의 서비스를 통해 데이터 파이프라인을 구축할 수 있으며, 이들 서비스는 서로 유기적으로 통합되어 동작한다.

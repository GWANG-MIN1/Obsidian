# AWS Config & AWS Audit Manager

## AWS Config란?

**AWS Config**는 AWS 리소스의 구성을 지속적으로 **모니터링(Monitoring)** 하고 **기록(Recording)** 하며, 미리 정의한 규칙에 따라 **규정 준수 여부를 평가(Evaluate)** 하는 서비스이다.

즉,

> **현재 AWS 리소스 구성이 회사 정책이나 규정 준수 기준을 만족하는지 지속적으로 확인하는 서비스이다.**

---

# AWS Config가 필요한 이유

AWS에서 리소스를 생성한 후 다음과 같은 궁금증이 생길 수 있다.

- 현재 리소스가 회사의 보안 정책을 준수하는가?
- 아키텍처가 조직의 표준(Standard)을 만족하는가?
- 규정 위반이 발생한 리소스는 없는가?

AWS Config는 이러한 질문에 대한 답을 제공한다.

---

# AWS Config 동작 방식

```
AWS 리소스 생성 또는 변경
            ↓
AWS Config가 구성(Configuration) 기록
            ↓
규칙(Rules)과 비교
            ↓
규정 준수 여부 평가
            ↓
보고서 생성 및 결과 확인
```

---

# AWS Config의 주요 기능

### 1. 리소스 구성 모니터링

AWS 리소스의 구성을 지속적으로 모니터링하고 변경 사항을 기록한다.

예시
- EC2 보안 그룹 변경
- S3 버킷 설정 변경
- IAM 정책 변경

---

### 2. 변경 사항 지속 추적

리소스 구성이 변경될 때마다 변경 이력을 자동으로 기록한다.

이를 통해

- 누가 변경했는지
- 언제 변경했는지
- 무엇이 변경되었는지

확인할 수 있다.

---

### 3. 규칙(Rules) 기반 평가

미리 정의된 규칙이나 사용자 지정 규칙(Custom Rules)을 이용하여 리소스를 평가한다.

예시

- S3 버킷은 반드시 암호화를 사용해야 한다.
- 보안 그룹은 0.0.0.0/0으로 SSH(22번 포트)를 허용하면 안 된다.
- EBS 볼륨은 암호화되어 있어야 한다.

규칙을 만족하지 못하면 **Non-compliant(규정 미준수)** 로 표시된다.

---

### 4. 사용자 지정 규칙(Custom Rules)

회사 정책에 맞는 규칙을 직접 생성할 수 있다.

예시

- 모든 EC2 인스턴스는 특정 태그(Tag)를 가져야 한다.
- 개발 계정에서는 특정 인스턴스 타입만 사용할 수 있다.
- 모든 데이터베이스는 백업을 활성화해야 한다.

---

### 5. 규정 준수 보고서 생성

AWS Config는 어떤 리소스가

- 규정을 준수하는지(Compliant)
- 규정을 준수하지 않는지(Non-compliant)

한눈에 확인할 수 있는 보고서를 생성한다.

---

# AWS Config 핵심 개념

> **규정 준수는 한 번 확인하고 끝나는 것이 아니라 지속적으로 관리해야 한다.**

AWS Config는 리소스 변경을 계속 추적하며 규정 준수 상태를 지속적으로 평가한다.

특히

- 금융 회사
- 의료 회사
- 공공기관

처럼 높은 수준의 규정 준수가 필요한 환경에서 많이 사용된다.

---

# AWS Audit Manager

**AWS Audit Manager**는 규정 준수 감사(Audit)에 필요한 **증거(Evidence)를 자동으로 수집**하여 감사 업무를 간소화하는 서비스이다.

감사에 필요한 수작업을 줄이고, 규정 준수 증빙 자료를 자동으로 준비할 수 있다.

---

# AWS Audit Manager의 주요 기능

### 1. 증거(Evidence) 자동 수집

AWS 서비스에서 감사에 필요한 증거를 자동으로 수집한다.

예시

- IAM 설정
- CloudTrail 로그
- AWS Config 평가 결과

---

### 2. 정책 평가(Policy Assessment)

조직의 정책과 규정 준수 요구사항을 평가한다.

---

### 3. 검토 관리(Review Management)

감사 진행 상황과 검토 작업을 체계적으로 관리할 수 있다.

---

### 4. 감사 보고서 자동 생성

감사에 바로 사용할 수 있는 보고서를 자동으로 생성한다.

이를 통해 수작업을 크게 줄일 수 있다.

---

### 5. 미리 구축된 프레임워크 제공

AWS에서 제공하는 다양한 규정 준수 프레임워크를 사용할 수 있다.

예시

- GDPR
- HIPAA
- PCI DSS
- ISO 27001

---

# AWS Config vs AWS Audit Manager

| AWS Config | AWS Audit Manager |
|------------|-------------------|
| 리소스 구성을 지속적으로 모니터링 | 감사(Audit) 증거를 자동 수집 |
| 규칙 기반 규정 준수 평가 | 감사 보고서 및 증빙 자료 생성 |
| 리소스 변경 사항 추적 | 감사 업무 자동화 |
| 규정 준수 여부 확인 | 규정 준수를 입증하는 자료 제공 |

---

# AWS Config + Audit Manager

```
AWS 리소스 생성
        ↓
AWS Config
- 구성 기록
- 규칙 평가
- 규정 준수 확인
        ↓
AWS Audit Manager
- 증거 자동 수집
- 감사 보고서 생성
- 감사 업무 자동화
```

---

# 핵심 정리

- **AWS Config** : AWS 리소스 구성을 지속적으로 모니터링하고 규칙에 따라 규정 준수 여부를 평가하는 서비스
- 변경 사항 추적, 사용자 지정 규칙 생성, 규정 준수 보고서 생성 가능
- 규정 준수는 일회성이 아니라 지속적으로 관리해야 한다.
- **AWS Audit Manager** : 감사에 필요한 증거를 자동 수집하고 보고서를 생성하여 감사 업무를 자동화하는 서비스
- Audit Manager는 정책 평가, 검토 관리, 감사 보고서 생성 및 다양한 규정 준수 프레임워크를 제공한다.

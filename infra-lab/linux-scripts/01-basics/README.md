# 01 리눅스 기초

리눅스는 **"모든 것은 파일"** 이라는 철학 위에 세워졌다. 디렉터리·장치·프로세스·소켓까지 파일처럼 다루기 때문에, 파일시스템 구조와 셸을 이해하는 것이 모든 것의 출발점이다.

---

## 파일시스템 계층 (FHS)

리눅스는 단일 루트 `/` 아래에 표준화된 디렉터리 트리를 갖는다 (Filesystem Hierarchy Standard).

```
/
├── bin    → 기본 실행 명령어 (ls, cp)
├── boot   → 부트로더·커널 이미지
├── dev    → 장치 파일 (disk, tty)
├── etc    → 시스템 전역 설정 파일
├── home   → 일반 사용자 홈 디렉터리
├── lib    → 공유 라이브러리
├── opt    → 서드파티 애플리케이션
├── proc   → 커널·프로세스 정보 (가상 파일시스템)
├── root   → root 사용자 홈
├── sys    → 커널·장치 정보 (가상)
├── tmp    → 임시 파일 (재부팅 시 삭제 가능)
├── usr    → 사용자 프로그램·문서
└── var    → 가변 데이터 (로그·캐시·스풀)
```

| 디렉터리 | 자주 보는 것 |
|----------|--------------|
| `/etc` | `passwd`, `hosts`, `fstab`, `ssh/sshd_config` — 서버 설정의 중심 |
| `/var/log` | 시스템·서비스 로그 (`syslog`, `nginx/`) |
| `/proc` | `cpuinfo`, `meminfo`, `/proc/<PID>/` — 실시간 커널 상태 |
| `/dev` | `null`, `zero`, `sda`, `tty` — 장치 |

> `/proc`, `/sys`는 디스크에 없는 **가상 파일시스템**이다. 커널이 메모리 상태를 파일처럼 보여준다 — 컨테이너의 cgroups/namespace도 여기에 노출된다.

## 셸(Shell)이란

셸은 사용자가 입력한 명령을 커널에 전달하는 **명령 해석기**다. 대부분의 배포판은 `bash`를, 최신 macOS·일부 배포판은 `zsh`를 기본으로 쓴다.

```bash
echo $SHELL          # 현재 셸 확인
cat /etc/shells      # 사용 가능한 셸 목록
```

명령의 기본 구조:

```
명령어 [옵션] [인자]
  ls    -alh   /var/log
```

---

## 기본 탐색

```bash
pwd                  # 현재 위치 (print working directory)
ls -alh              # 숨김파일(a)·상세(l)·크기(h)
cd /etc              # 절대 경로 이동
cd ..                # 상위 디렉터리
cd -                 # 직전 디렉터리로 토글
cd ~                 # 홈 디렉터리
```

### 경로 표기

| 기호 | 의미 |
|------|------|
| `/` | 루트 (절대 경로 시작) |
| `.` | 현재 디렉터리 |
| `..` | 상위 디렉터리 |
| `~` | 현재 사용자 홈 |
| `-` | 직전 작업 디렉터리 |

## 파일·디렉터리 조작

```bash
touch file.txt              # 빈 파일 생성 / 타임스탬프 갱신
mkdir -p logs/2026/07       # 중간 경로까지 생성
cp -r src/ dst/             # 디렉터리 재귀 복사
mv old.txt new.txt          # 이동 / 이름 변경
rm file.txt                 # 파일 삭제
rm -rf dir/                 # 디렉터리 강제 재귀 삭제 (복구 불가, 주의)
ln -s /opt/app/current link # 심볼릭 링크
```

> `rm -rf`는 되돌릴 수 없다. 변수를 쓸 땐 `rm -rf "$DIR"/`처럼 따옴표로 감싸 공백·빈 변수로 인한 참사를 막는다.

## 파일 내용 확인

```bash
cat file            # 전체 출력
less file           # 페이지 단위 (q 종료, / 검색)
head -n 20 file     # 앞 20줄
tail -n 20 file     # 뒤 20줄
tail -f app.log     # 실시간 추적 (로그 볼 때 핵심)
```

---

## 파일 찾기

```bash
find /etc -name "*.conf"          # 이름으로 검색
find . -type f -mtime -1          # 최근 1일 내 수정된 파일
find / -size +100M 2>/dev/null    # 100MB 초과 (에러 숨김)
which ls                          # 실행 파일 경로
type cd                           # 명령 종류 (내장/외부)
```

## 도움말 보기

```bash
man ls               # 매뉴얼 페이지 (q 종료)
ls --help            # 간단 옵션 요약
tldr tar             # 실용 예제 중심 (별도 설치)
```

## 배운 점
- 리눅스는 **모든 것을 파일로** 다룬다 — 장치·프로세스·커널 상태까지
- FHS 표준 덕분에 어느 배포판이든 `/etc`(설정)·`/var/log`(로그)·`/proc`(상태) 위치가 같다
- 셸은 명령 해석기, `명령어 [옵션] [인자]` 구조가 기본
- `tail -f`, `find`, `less`는 서버 운영에서 매일 쓰는 도구
- `rm -rf`는 되돌릴 수 없으니 변수·경로를 항상 신중히

# Troubleshooting

실제로 막혔던 것들의 기록. 학습 노트(`../linux-scripts/`, `../docker-labs/` 등)가 "무엇을 배웠나"라면,
여기는 **"무엇에 걸렸고 왜 그랬나"** 다.

## 형식

```
## 현상       무엇이 어떻게 안 됐는가 (에러 메시지 원문 포함)
## 환경       OS/버전/구성 — 재현에 필요한 최소 정보
## 진단       가설 → 검증 → 반증의 과정 (막다른 길도 남긴다)
## 원인       왜 그랬는가 (추측이 아니라 확인한 근거)
## 해결       실제로 통한 명령·설정
## 재발 방지   다음에 안 겪으려면 무엇을 바꿔야 하는가
```

## 원칙

- **추측을 근거로 쓰지 않는다.** "아마 ~때문일 것"은 원인이 아니다. 명령 출력으로 확인한 것만 원인에 적는다.
- **반증된 가설도 남긴다.** 왜 그 방향으로 갔는지가 다음 사람(과 미래의 나)에게 유용하다.
- **재현 절차를 남긴다.** 재현할 수 없으면 해결됐는지도 확인할 수 없다.
- **재발 방지가 핵심이다.** 고친 것으로 끝나면 다음에 또 겪는다.

> 포스트모템과 같은 규율을 요구한다 — 근본 원인 하나가 아니라 **확인한 근거**.

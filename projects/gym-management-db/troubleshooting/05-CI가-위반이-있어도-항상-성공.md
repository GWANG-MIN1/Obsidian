# 05. 린트·스키마 검사가 위반이 있어도 항상 성공했다

- **발생**: 2026-09-05 (발견)
- **증상 한 줄**: SQL에 위반이 있고 psql이 오류를 내는데도 워크플로우는 초록색

---

## 현상

배지가 전부 초록이었다. 그런데 실제로 린트를 돌려 보면 위반이 19개 있었다.

```
   8 file=01_create_tables.sql LT01
   5 file=01_create_tables.sql RF04
   4 file=03_project_queries.sql LT02
   2 file=03_project_queries.sql RF02
```

## 환경

- GitHub Actions / sqlfluff / psql (postgres:15 서비스 컨테이너)

## 진단

### 1) 린트 워크플로우

```yaml
- name: Run SQL lint
  run: sqlfluff lint *.sql --dialect oracle || true

- name: Fix SQL formatting
  run: sqlfluff fix *.sql --dialect oracle --force || true
```

`|| true`가 붙어 있으면 앞 명령이 실패해도 셸은 성공으로 끝난다.
**어떤 위반이 있어도 이 단계는 통과한다.**

그리고 `sqlfluff fix` 단계는 CI에서 파일을 고치지만 **그 결과는 커밋되지 않는다.**
러너가 사라지면 같이 사라진다. 아무 일도 하지 않는 단계였다.

이 `|| true`는 [4개월 전에 내가 넣은 것이었다](08-린트를-우회했다가-검증이-무력화.md).

### 2) 스키마 테스트 워크플로우

```yaml
- name: Apply schema
  run: psql -f sql/01_create_tables_pg.sql
```

`psql`은 기본적으로 **SQL 오류가 나도 남은 문장을 계속 실행하고 종료 코드 0으로 끝난다.**
스키마가 절반만 만들어져도 워크플로우는 성공이다.

### 3) 정리하면

| 워크플로우 | 실패할 수 있는가 |
|---|---|
| SQL Lint | 아니오 (`\|\| true`) |
| Schema Test | 아니오 (`ON_ERROR_STOP` 없음) |
| CD | 빌드·배포 실패 시에만 |

**"CI가 초록색이다"가 아무것도 보증하지 않는 상태였다.**

## 원인

검증 단계가 **실패할 수 없게** 설정돼 있었다.

## 해결

**린트** — `|| true`와 의미 없는 fix 단계를 제거하고 버전을 고정했다. `sql/`은 postgres 방언으로 분리.

```yaml
- name: Install sqlfluff
  run: pip install sqlfluff==4.3.0

- name: Lint Oracle SQL (repo root)
  run: sqlfluff lint *.sql

- name: Lint PostgreSQL SQL (sql/)
  run: sqlfluff lint sql/
```

통과시키기 위해 실제 위반도 고쳤다.
자동 수정으로 되는 것(LT01/LT02)은 `sqlfluff fix`로, 서브쿼리 참조 한정(RF02)은 직접,
컬럼명이 예약어라 나는 RF04는 **이유를 적고 `exclude_rules`에 명시**했다.

**스키마 테스트** — 모든 `psql` 호출에 `-v ON_ERROR_STOP=1`을 붙이고,
"제약 위반은 거부되어야 함" 단계를 추가했다.

```bash
assert_rejected() {
  if psql -v ON_ERROR_STOP=1 -q -c "$1" >/dev/null 2>&1; then
    echo "::error::허용되면 안 되는 SQL 이 통과했습니다 — $2"
    exit 1
  fi
  echo "거부됨(정상): $2"
}
```

```
거부됨(정상): 존재하지 않는 시각 99:99
거부됨(정상): 전화번호 중복
거부됨(정상): 잔여 PT 횟수 음수
거부됨(정상): 같은 트레이너·시간대 중복 예약
거부됨(정상): 결제 금액 음수
```

**CD** — 배포 전에 API 테스트를 통과하도록 `test` 잡을 앞에 붙였다.

커밋 `adf4b1d`.

## 재발 방지

- `|| true`, `continue-on-error: true`를 검증 단계에 쓰지 않는다.
- 규칙을 지킬 수 없으면 **우회하지 말고 규칙을 명시적으로 끈다.** `exclude_rules`에 이유와 함께 적으면 나중에 판단을 되짚을 수 있다.
- 도구 버전을 고정한다. 고정하지 않으면 새 규칙이 추가되는 날 갑자기 빌드가 깨지고, 그게 다시 우회할 이유가 된다.
- **검증이 실패하는 것을 한 번은 확인한다.** 일부러 위반을 넣어 빨간불을 본 적이 없으면, 그 검증은 동작한다고 말할 수 없다.

## 배운 점

**초록불은 "문제가 없다"가 아니라 "설정된 검사를 통과했다"는 뜻이다.**
무엇을 검사하는지 모르면 초록불은 아무 의미가 없다.

`psql`처럼 **기본값이 관대한 도구**가 있다. 오류가 나도 계속 진행하고 0을 돌려준다.
CI에서 쓰는 도구는 실패했을 때 어떻게 끝나는지 먼저 확인해야 한다.

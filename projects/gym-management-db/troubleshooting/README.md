# Troubleshooting

gym-management-db 에서 실제로 막혔던 것들.
형식과 원칙은 `../../../infra-lab/troubleshooting/README.md` 와 같다.

```
## 현상       무엇이 어떻게 안 됐는가 (에러 메시지 원문 포함)
## 환경       재현에 필요한 최소 정보
## 진단       가설 → 검증 → 반증의 과정 (막다른 길도 남긴다)
## 원인       왜 그랬는가 (확인한 근거로)
## 해결       실제로 통한 명령·설정
## 재발 방지   다음에 안 겪으려면 무엇을 바꿔야 하는가
## 배운 점
```

## 이 프로젝트에서 특히 남길 만한 것

- **03** 은 원인을 처음에 "인덱스가 없어서"로 잘못 짚었다가 뒤집은 사례다.
  볼트 원칙의 *"반증된 가설도 남긴다"* 에 해당한다.
- **06** 은 로컬에서 재현되지 않는 종류의 실패다. 왜 로컬에서만 통과했는지가 핵심.

## 아직 안 쓴 소재

- push가 거부됨 — PAT에 `workflow` 스코프가 없어서
- 워크플로우 배지가 `no status` — 재사용 워크플로우 호출은 별도 실행으로 집계되지 않음

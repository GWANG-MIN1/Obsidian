# Decisions

이 프로젝트에서 **무엇을 왜 그렇게 정했는가**의 기록.
`../troubleshooting/` 이 "막힌 것"이라면 여기는 "고른 것"이다.

## 형식

```
## 상황              무엇을 정해야 했는가
## 결정              무엇을 택했는가
## 왜                근거 — 확인한 사실 기준으로
## 왜 다른 건 안 썼나   버린 선택지와 그 이유
```

필요하면 `## 결과`(그래서 어떻게 됐는가, 어떻게 검증했는가)를 덧붙인다.

## 원칙

- **버린 이유가 핵심이다.** "Alembic을 썼다"는 누구나 말한다.
  "트리거로 하면 로컬과 배포에서 차감이 두 번 일어나서 안 썼다"는 해본 사람만 말한다.
- **근거는 확인한 것만 적는다.** 트러블슈팅 노트와 같은 규율.
  "아마 더 빠를 것 같아서"는 근거가 아니다.
- **나중에 뒤집힌 결정도 남긴다.** 왜 그때 그렇게 판단했는지가 기록의 값이다.
- 재사용 가능한 지식(부분 유니크 인덱스가 무엇인가 등)은 여기 말고 `../../../infra-lab/` 에 두고 링크한다.

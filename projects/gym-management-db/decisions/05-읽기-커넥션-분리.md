# 05. 읽기 전용 커넥션 분리

> 메모: Terraform으로 Replica를 만들어도 앱이 엔진 하나만 쓰면 분산이 안 됨. 시크릿의 replica_host 유무로 읽기 세션만 분리

---

## 상황

Terraform에 `create_read_replica` 옵션이 있고, README에는 "Read Replica를 활성화해 읽기 쿼리를 분산"이라고 적혀 있었다.

그런데 **API는 Primary에 연결된 엔진 하나만 쓰고 있었다.**
변수를 켜면 Replica 인스턴스는 생기지만 요청은 전부 Primary로 간다. 돈만 더 나간다.

## 결정

읽기 전용 세션을 따로 만들고, **Replica가 있을 때만** 그쪽으로 연결한다.

```python
DATABASE_URL, READ_DATABASE_URL = _resolve_urls()
READ_REPLICA_ENABLED = READ_DATABASE_URL != DATABASE_URL

engine = create_engine(DATABASE_URL, **_ENGINE_OPTIONS)
read_engine = engine if not READ_REPLICA_ENABLED else create_engine(READ_DATABASE_URL, ...)
```

Replica의 존재는 **Secrets Manager 시크릿의 `replica_host` 유무**로 판단한다.
Terraform이 `create_read_replica = true`일 때만 그 키를 넣는다.

```hcl
secret_string = jsonencode(merge(
  { username = ..., host = aws_db_instance.primary.address, ... },
  var.create_read_replica ? { replica_host = aws_db_instance.replica[0].address } : {}
))
```

라우터는 조회에 `get_read_db`, 쓰기에 `get_db`를 쓴다.

## 왜

- **인프라 설정과 앱 동작이 한 곳에서 이어진다.** Terraform 변수를 켜면 시크릿이 바뀌고, 앱은 시크릿만 보면 된다. 앱 코드나 환경변수를 따로 고칠 필요가 없다.
- **Replica가 없어도 그대로 돈다.** 없으면 읽기 세션이 Primary를 가리킨다. 기본값이 안전한 쪽.
- 로컬에서도 `READ_DATABASE_URL` 환경변수로 같은 경로를 시험할 수 있다.

## 왜 다른 건 안 썼나

**항상 Replica로 연결**

Replica가 없는 dev 환경에서 기동 자체가 실패한다.

**라우터마다 엔진을 골라 쓰기**

어디는 분리하고 어디는 안 하는 상태가 된다. 의존성(`get_read_db`) 하나로 결정하면 라우터는 "읽기냐 쓰기냐"만 선언하면 된다.

## 남은 한계

`/health`는 **Primary에만** `SELECT 1`을 던진다.
Replica가 끊겨도 헬스체크는 200이고, 그 상태에서 목록 조회만 실패한다.
실제로 Replica를 운영한다면 헬스체크에 읽기 커넥션 확인을 넣고 장애 시 Primary로 넘어가는 처리가 필요하다. README에도 적어 뒀다.

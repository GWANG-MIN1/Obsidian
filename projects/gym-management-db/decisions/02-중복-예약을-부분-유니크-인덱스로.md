# 02. 중복 예약 방지를 부분 유니크 인덱스로

> 메모: 일반 UNIQUE 제약은 취소된 예약도 슬롯을 계속 점유함. WHERE status <> 'CANCELLED' 로 취소 시 슬롯이 비도록

---

## 상황

5월 스키마에는 트레이너 기준 중복 예약만 막혀 있었다.

```sql
UNIQUE (trainer_id, session_date, session_time)
```

두 가지가 문제였다.

1. **같은 회원**이 다른 트레이너에게 같은 시간을 예약하는 건 막히지 않았다. 몸이 하나인데.
2. 예약을 **취소해도 그 슬롯이 계속 점유됐다.** 취소한 시간에 다시 예약하면 409.

## 결정

두 제약 모두 **부분 유니크 인덱스**로 만든다.

```sql
CREATE UNIQUE INDEX uq_trainer_slot
    ON PT_Session (trainer_id, session_date, session_time)
    WHERE status <> 'CANCELLED';

CREATE UNIQUE INDEX uq_member_slot
    ON PT_Session (member_id, session_date, session_time)
    WHERE status <> 'CANCELLED';
```

## 왜

- **"취소된 예약은 슬롯을 비운다"는 업무 규칙을 DB가 직접 표현한다.** 조건이 인덱스 정의에 들어 있으니 어느 코드 경로로 들어와도 같은 규칙이 적용된다.
- 취소 이력을 지우지 않고도 슬롯이 빈다. `CANCELLED` 행은 그대로 남아 기록이 된다.
- 위반은 DB가 잡고, API는 [결정 09](09-오류-매핑을-제약-이름-기준으로.md)의 매핑으로 409와 설명을 돌려준다.

검증:

```
취소된 슬롯 재예약 -> 18
중복 예약 -> 거부됨: uq_trainer_slot
```

## 왜 다른 건 안 썼나

**일반 UNIQUE 제약 유지**

취소 후 재예약이 안 된다. 실제로 5월 스키마가 그랬고, 마이그레이션 `0002`에서 제약을 떼고 부분 인덱스로 바꿨다.

**애플리케이션에서 조회 후 INSERT**

두 요청이 동시에 들어오면 둘 다 "빈 슬롯"으로 보고 통과한다. 유일성은 DB가 보장해야 한다.

**취소 시 행을 삭제**

슬롯은 비지만 취소 이력이 사라진다. 누가 언제 취소했는지가 운영에서는 필요한 정보다.

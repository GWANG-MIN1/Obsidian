# 08. 테스트를 SQLite 대신 실제 PostgreSQL로

> 메모: 정규식 CHECK와 부분 유니크 인덱스가 PostgreSQL 전용이라 SQLite로는 검증이 안 됨. CI에 서비스 컨테이너를 띄우는 비용을 감수함

---

## 상황

API 테스트를 처음 붙이면서 테스트 DB를 뭘로 할지 정해야 했다.
SQLite in-memory는 빠르고 설치할 게 없다. 파이썬 테스트에서 가장 흔한 선택이다.

## 결정

**실제 PostgreSQL**에 붙여 테스트한다.

- CI: GitHub Actions 서비스 컨테이너 (`postgres:15`)
- 로컬: docker compose의 DB에 **별도 데이터베이스**(`gymdb_test`)

## 왜

검증하려는 것 상당수가 **PostgreSQL 전용**이다.

| 검증 대상 | SQLite에서 |
|---|---|
| 예약 시각 CHECK — `session_time ~ '^([01][0-9]\|2[0-3]):[0-5][0-9]$'` | `~` 연산자 없음 → 테이블 생성부터 실패 |
| 부분 유니크 인덱스 — `WHERE status <> 'CANCELLED'` | 지원하지만 의미가 다름 |
| `GENERATED ALWAYS AS IDENTITY` | 없음 |
| 제약 이름 기반 오류 매핑 (`psycopg2` `diag.constraint_name`) | 드라이버가 다름 → 매핑 자체가 동작 안 함 |
| 범위 초과 숫자에서 나는 22003 오류 | 정수 범위가 다름 |

SQLite로 갔다면 **"테스트는 통과하는데 배포하면 깨지는"** 구조가 됐을 것이다.
이 프로젝트에서 실제로 문제가 된 것들이 전부 위 목록에 있다.

## 왜 다른 건 안 썼나

**SQLite in-memory**

위 표대로 핵심 검증이 전부 빠진다. 빠른 대신 **검증하려던 것을 검증하지 못한다.**

**DB를 모킹**

무결성 제약이 실제로 동작하는지가 검증 대상인데, 그걸 모킹하면 남는 게 없다.

## 대가

- CI에 서비스 컨테이너가 필요하다 (실행 시간 증가, 실제로는 1분 이내).
- 로컬에서 테스트하려면 DB가 떠 있어야 한다.
- **테스트가 테이블을 지운다.** 이 대가가 실제 사고로 이어졌다 → [트러블 01](../troubleshooting/01-테스트가-개발DB-테이블을-삭제.md).
  지금은 `TEST_DATABASE_URL`만 받고 이름이 `_test`로 끝나지 않으면 실행을 거부한다.

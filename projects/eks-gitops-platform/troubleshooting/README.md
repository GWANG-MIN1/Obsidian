# Troubleshooting

eks-gitops-platform 에서 실제로 막혔던 것들.
형식과 원칙은 [`../../../infra-lab/troubleshooting/README.md`](../../../infra-lab/troubleshooting/README.md) 와 같다.

```
## 현상       무엇이 어떻게 안 됐는가 (에러 메시지 원문 포함)
## 환경       재현에 필요한 최소 정보
## 진단       가설 → 검증 → 반증의 과정 (막다른 길도 남긴다)
## 원인       왜 그랬는가 (확인한 근거로)
## 해결       실제로 통한 명령·설정
## 재발 방지   다음에 안 겪으려면 무엇을 바꿔야 하는가
## 배운 점
```

## 이 저장소의 기록 방식 — 원문은 저장소에 있다

다른 프로젝트와 달리 **실패가 이미 문서로 있다.** 저장소의 `docs/troubleshooting/01~05` 가
증상 → 진단(명령 · 출력) → 해결 → 교훈 형식으로 적혀 있고, 검증 기록 4개가 앞뒤 맥락을 담는다.

그래서 여기엔 명령 출력 원문을 옮기지 않는다. 각 노트는 저장소 문서를 **원문**으로 링크하고, 저장소 문서가 안 적은 것 세 가지를 더한다.

- **환경** — 버전 · 노드 수 · 그날의 Phase
- **재발 방지가 실제로 반영됐는가** — 교훈으로 적은 것이 코드에 들어갔는지, 09-14 기준으로 확인
- **원인의 정확한 조건** — 예: max-pods 17 의 계산식, `selectableFields` 가 "1.31+ 기능"이라는 말의 정확한 뜻

## 이 프로젝트에서 특히 남길 만한 것

- **03** 이 가장 밀도가 높다. 첫 가설(caBundle)을 명령 한 줄로 반증하고, 차트 원본과 라이브 CRD 를 대조해 원인에 도달했다.
  그 원인이 [결정 03](../decisions/03-전부-버전을-고정했다.md) 의 버전 조합 문제로 이어진다.
- **01 · 02 · 03** 은 07-20 한 저녁에 나왔고, 전부 **정적 검사로는 원리적으로 안 잡히는** 종류다. validate 도, 차트 렌더링도 초록이었다.
- **04 · 05** 는 버그가 아니라 **매일 destroy 의 부작용**이다. 문제가 코드가 아니라 워크플로우에 있으니 재발 방지도 절차에 있어야 했다.

**5건 중 코드로 막은 것은 둘(02 · 03)이다.** 교훈으로 적힌 것과 코드에 들어간 것은 다르다.
그리고 저장소 트러블슈팅 README 의 *"전부 Git 수정 → push 로 해결"* 도 그 둘에만 맞는 문장이다.

## 노트로 안 쓴 사소한 것 (저장소 검증 기록에 있음)

- Grafana Explore 의 기본 데이터소스가 Prometheus 라 로그가 "No data" 로 보인다 — 좌상단에서 Loki 로 바꿔야 한다
- `aws` CLI 에 `--region ap-northeast-2` 를 빼면 기본 리전을 조회해서 빈 결과가 나온다
- PowerShell 에선 bash 식 `\` 줄바꿈이 안 먹는다 — 명령을 한 줄로
- ArgoCD 설치 직후 root-app 을 바로 적용하면 repo-server 가 아직 안 떠서 첫 비교가 `Unknown` 으로 남는다 (1~2분 내 자동 회복)

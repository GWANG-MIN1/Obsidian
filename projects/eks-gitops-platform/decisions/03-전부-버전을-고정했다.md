# 03. 전부 버전을 고정했다 — 그리고 고정한 것이 늙었다

> 메모: `stable` 태그 대신 ArgoCD v2.13.4, 차트 · 액션 · 이미지까지 버전을 박았다. 올릴 때 한 줄짜리 리뷰 가능한 변경이 되게.
> 2026-07-13 ~ 07-16, `7c85049` 외. **대가는 이 노트를 쓰며(09-14) 확인했다.**

---

## 상황

설치물이 많다 — 쿠버네티스 자체, ArgoCD, Helm 차트 5개, GitHub Action, kube-bench 이미지, Terraform 모듈 2개.
매일 destroy 하고 다시 만드는 저장소라 **"어제와 같은 것이 뜨는가"** 가 중요했다.

## 결정

| 대상 | 고정값 | 어디 |
|---|---|---|
| Kubernetes (EKS) | `1.30` | `variables.tf` · `tfvars.example` · 모듈 기본값 |
| ArgoCD | v2.13.4 (install.yaml URL) | `gitops/bootstrap/argocd/kustomization.yaml` |
| kube-prometheus-stack | 87.16.1 | Application |
| loki / promtail | 6.55.0 / 6.17.1 | Application — *"7.0.0 은 갓 나온 메이저라, 이 클러스터가 그 버그를 찾을 필요는 없다"* |
| kyverno / external-secrets | 3.8.2 (Kyverno v1.18.2) / 2.7.0 | Application |
| trivy-action · kube-bench | v0.36.0 · v0.15.6 | 워크플로우 · Job |
| Terraform 모듈 | eks `~> 20.24` · vpc `~> 5.13` | 모듈 |

## 왜

- ArgoCD 커밋 본문 — *"고정되지 않은 `stable` 매니페스트를 curl 하는 대신"*. 올리는 일이 **리뷰 가능한 한 줄**이 된다.
- 매일 재생성하는데 범위 버전이면 날마다 다른 것이 뜬다. 어제 고친 문제가 오늘 **다른 이유로** 재발하면 원인을 못 가른다.
- 실제로 07-22 재생성에서 지난 세션의 수정(Loki · CRD)이 그대로 먹혔다. 고정이 준 재현성이다.

## 왜 다른 건 안 썼나

**`stable` · 최신 차트**

재현성이 없다. 위의 이유 전부.

**고정 + 자동 갱신 PR (Renovate · Dependabot)**

[security-lab/07](../../../infra-lab/security-lab/07-image-security/README.md) 이 자동 갱신을 다룬다. 이 저장소엔 안 붙였고 이유는 안 적혀 있다.
12일짜리 프로젝트라 필요가 없다고 봤을 수 있다(추정). 아래 대가를 보면 **필요했다.**

## 이 결정의 대가 — 고정은 늙는 속도를 통제하지 못한다

### ① 차트는 최신, 쿠버네티스는 오래된 조합

차트들은 고정한 날(07-16) 기준 최신 릴리스(Kyverno v1.18.2 · ESO 2.7.0)였는데 쿠버네티스는 1.30 이었다.
그 틈이 [트러블 03](../troubleshooting/03-Healthy인데-영원히-OutOfSync.md) 이다 — 차트가 만든 CRD 의 `selectableFields` 를
1.30 API 서버가 조용히 버렸다. 이 필드는 **1.30 에서 알파(기본 꺼짐), 1.31 에서 베타(기본 켜짐)** 이고,
EKS 는 알파 기능을 지원하지 않는다.

**각각을 고정한 것은 맞았는데, 고정한 값들끼리의 호환성은 아무도 고정하지 않았다.**

### ② 1.30 은 검증 당시 이미 연장 지원의 마지막 나흘이었다

| EKS 1.30 | 날짜 |
|---|---|
| EKS 출시 | 2024-05-23 |
| 표준 지원 종료 | 2025-07-23 |
| **연장 지원 종료** | **2026-07-23** ← Phase 4 검증일 |

- **요금** — 연장 지원 구간의 클러스터는 시간당 **$0.60** (표준 $0.10). AWS 의 기본 업그레이드 정책이 `EXTENDED` 라
  따로 설정하지 않으면 그대로 과금된다. 저장소 어디에도 "연장 지원"이라는 말이 없다. → [결정 02](02-매일-destroy를-전제로-설계했다.md)
- **생성** — AWS 문서: *"연장 지원 종료일부터는 그 버전으로 새 클러스터를 만들 수 없다."*
  07-23 이후 이 저장소의 기본값으로는 `terraform apply` 가 클러스터 생성에서 막힌다. **(직접 apply 해서 확인하진 않았다)**
- **대안이 있었다** — 같은 7월에 EKS 표준 지원 버전은 1.33 ~ 1.36 이었다. 왜 1.30 인지는 적혀 있지 않다.

**"매일 부수고 다시 만든다"를 전제로 설계했는데, 두 달 뒤 기본값으로는 다시 만들 수 없게 됐다.**
코드는 한 줄도 안 바뀌었다. 바뀐 것은 AWS 캘린더다.

### ③ 고정의 구멍 두 개

- **`.terraform.lock.hcl` 을 gitignore 했다.** 프로바이더는 `~> 5.0` · `>= 5.40` 범위로만 묶여 있어서
  CI 와 내 PC 가 다른 AWS 프로바이더 버전을 받을 수 있다. 차트 버전은 박으면서 프로바이더는 안 박았다.
- **CI 의 Terraform 은 1.6.6, 검증에 쓴 로컬은 v1.14.3** (Phase 1 검증 기록). CI 가 초록인 것과 로컬 apply 가 되는 것이
  같은 도구로 확인된 게 아니다.

### ④ 트러블 03 의 "제거 조건"이 강제로 도래했다

`kyverno.yaml` · `external-secrets.yaml` 의 `ignoreDifferences` 주석은 *"클러스터가 1.31+ 가 되면 제거"* 다.
1.30 으로는 이제 못 만드니, 다음에 클러스터를 띄우는 순간 이 규칙은 **아무것도 안 가리는 잔재**가 된다.
그리고 1.31 도 이미 연장 지원 구간(2025-11-26 표준 종료)이라, 다음 재생성은 1.34 이상이 맞다.

## 배운 점

**버전 고정은 "무엇이 뜨는가"를 고정하지만 "그것이 언제까지 뜰 수 있는가"는 고정하지 못한다.**
고정값에는 만료일이 있고, 그 만료일은 코드 밖(AWS 캘린더)에 있다. 고정할 때 **만료일도 같이 적어 두는** 게 빠졌다 —
[security-lab/07](../../../infra-lab/security-lab/07-image-security/README.md) 이 `.trivyignore` 예외마다 재검토 날짜를 적으라고 한 것과 같은 모양의 규칙이
버전 고정에도 필요했다.

**고정한 값들 사이의 호환성은 별도의 고정 대상이다.** [cicd-lab/05](../../../infra-lab/cicd-lab/05-argocd-advanced/README.md) 가
*"차트 버전 ≠ 클러스터 버전 호환"* 을 교훈 표에 적어 뒀는데, 그 교훈을 준 게 이 프로젝트다.

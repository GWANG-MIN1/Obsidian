## Phase 2 · 05-28 ~ 06-01 — MVP 조립 (Day 5~10, 커밋 29개)

```
Day 5  Lambda + DDB + Bedrock 통합         (aws lambda invoke 로만 호출)
  ↓
Day 6  Function URL + 응답 스트리밍          (HTTP 노출, 노선 변경)
  ↓
Day 7  Hono 멀티 라우트 + 히스토리 조회 API
  ↓
Day 8  Vite React 프론트 + S3 정적 호스팅
  ↓
Day 9  CloudFront 로 프론트 + API 통합       (same-origin)
  ↓
Day 10 Phase 2 회고 — 함정 12종, 실비용 $0.07
```

**05-29, Day 6 에서 첫 노선 변경이 있었다.** 로드맵엔 "API Gateway 연동"이라 적어 뒀는데,
원본 레포를 확인해 보니 Function URL 을 쓰고 있었다. 이유를 따라가 보니 API Gateway v1/v2 **둘 다
응답 스트리밍을 지원하지 않는다**. 챗봇에서 토큰을 흘리는 게 UX 핵심이라 노선을 바꿨다.
→ [결정 02](decisions/02-API-Gateway-대신-Function-URL.md)

**Day 7 에서 Day 5/6 의 버그를 뒤늦게 발견했다.** 히스토리 Query 가 `ScanIndexForward: true`,
즉 **가장 오래된 N개**를 가져오고 있었다. 세션이 길어지면 모델이 첫 대화만 컨텍스트로 받는다.
이력이 짧아서 티가 안 났을 뿐이다. 같은 날 정렬키도 합성으로 바꿨다.
→ [결정 03](decisions/03-정렬키를-타임스탬프-합성으로.md)

Day 10 회고에서 함정 12개를 세어 보고 남긴 문장이 이 프로젝트의 방법론을 정했다.

> 12개 중 9개가 "코드는 컴파일·deploy 되는데 실행 시점에 깨지는" 종류.
> `cdk synth` 만으로는 안 잡힘 — 실배포 + 실호출까지 가야 발견.

이후 모든 day 에 **실배포 + curl 검증 + 스크린샷**이 README 에 박히기 시작한다.

**Day 13 이 이 프로젝트의 분기점이다.** 여기서 "텍스트 생성기"가 "도구를 실행하는 에이전트"가 됐다.
Worker timeout 을 60초에서 5분으로 늘린 것이 그 전환의 물리적 표시다.

**06-01 에 Phase 3 플랜을 한 번 갈아엎었다.** 원본 레포의 실제 구성
(`packages/{backend,frontend,edge,shared}`, IoT Core, Lambda@Edge+SSM)을 다시 확인하고,
SQS·EventBridge·Cognito·API Gateway 는 **원본이 안 쓴다**는 이유로 플랜에서 제외했다.
"원본을 따라간다"는 목표를 지키려면 내가 아는 패턴이 아니라 **원본이 실제로 쓴 것**을 봐야 했다.

## 마침표 뒤 · 06-19 ~ 06-25 — 끝났다고 한 다음에 나온 것

**06-24, Day 20 스택을 새 환경에 재배포했더니 API 가 전 요청 500 을 뱉었다.**

```
Dynamic require of "util" is not supported
```

X-Ray SDK 가 ESM 번들 안에서 동적 `require()` 를 부르는데, esbuild 의 ESM 출력엔 `require` 가 없다.
**모듈 로드 시점**에 터지므로 요청이 핸들러에 닿지도 못한다. Worker 는 CJS 출력이라 멀쩡했다.
→ [트러블 12](troubleshooting/12-재배포하니-전-요청이-500.md) · 함정 #78 로 뒤늦게 번호를 붙였다.

이게 이 프로젝트의 가장 정직한 마무리다. **"검증했다"의 범위가 한 환경이었다는 뜻**이고,
자동 테스트가 없다는 빈칸이 정확히 여기서 드러났다.

같은 주에 남은 것들도 정리했다 — `npm audit fix`, 데모 스크린샷 보강,
캡스톤 아키텍처 다이어그램을 mermaid 에서 PNG 로 교체, 루트 README 에 데모 섹션 추가.

# 08. "오늘 AWS 비용 얼마야?" 에 0 이 나온다

- **발생**: 2026-06-08 (Day 17) · 저장소 함정 **#47 · #48 · #52**
- **증상 한 줄**: `awsCost` skill 이 성공하는데 오늘 비용이 항상 0

---

## 현상

Day 17 에서 `awsCost()` skill 을 샌드박스에 주입했다
([결정 10](../decisions/10-skill을-샌드박스에-주입.md)).
"이번 달 비용" 은 잘 나오는데 **"오늘 비용"은 언제나 0** 이다.

에러가 안 난다. `skillCalls` 에 `ok: true` 로 찍힌다.
Cost Explorer 가 정상 응답했고, 그 응답의 값이 0 이다.

## 환경

- AWS Cost Explorer `GetCostAndUsage`
- Worker Lambda 안 skill 함수
- 그 전에 이미 통과한 것: 계정 CE 활성화(#47), 클라이언트 리전 us-east-1 고정(#48)

## 진단

### 1) 먼저 밟은 두 개부터 (#47 · #48)

**#47 — `DataUnavailable` / AccessDenied**

Cost Explorer 는 계정에서 **한 번 켜야** 쓸 수 있다.
Billing 콘솔에서 Cost Explorer 를 열면 활성화되고, **데이터가 채워지는 데 ~24시간** 걸린다.
활성화 직후에 부르면 권한이 있어도 데이터가 없다.

**#48 — 엔드포인트 에러**

Cost Explorer 는 **us-east-1 단일 엔드포인트**다. 다른 리전으로 클라이언트를 만들면 안 된다.

```js
const ce = new CostExplorerClient({ region: "us-east-1" });   // 고정
```

Worker 자체가 us-east-1 에 있어서 우연히 안 걸릴 뻔했는데, 명시해 두는 게 맞다.

### 2) 그런데 오늘만 0 이다 (#52)

요청을 찍어 봤다.

```js
{ TimePeriod: { Start: "2026-06-08", End: "2026-06-08" }, Granularity: "DAILY", ... }
```

오늘 날짜를 시작과 끝에 똑같이 넣었다. 상식적으로 "오늘 하루"다.

**Cost Explorer 의 `TimePeriod.End` 는 exclusive 다.**

```
Start: 2026-06-08, End: 2026-06-08   →  [06-08, 06-08)  →  구간의 길이가 0
```

빈 구간을 조회했으니 0 이 맞다. **에러가 아니라 정확한 답이다.**

## 원인

**`TimePeriod.End` 가 exclusive 인데 inclusive 로 가정했다.**

이건 버그가 아니라 **API 계약을 잘못 읽은 것**이다.
그래서 에러도, 경고도 없고, 결과값만 조용히 틀린다.

## 해결

기본값에서 `end` 를 **내일**로 잡는다.

```js
async function getAwsCost({ start, end, granularity = "MONTHLY", metric = "UnblendedCost", ... } = {}) {
  // start/end 미지정 → 이번 달 1일 ~ 내일(exclusive)
  // 오늘을 포함하려면 end = 오늘 + 1일
  ...
}
```

기본값이 그렇게 동작하도록 만들어서, 모델이 날짜를 안 넘겨도 맞는 답이 나오게 했다.

## 왜 위험한 종류인가

이 문제는 **LLM 이 답을 지어내지 않아서 더 위험하다.**

모델은 skill 이 준 0 을 정직하게 전달한다. "오늘 비용은 $0 입니다."
사용자 입장에서는 **그럴듯하고 확신에 찬 틀린 답**이다.

에이전트에 외부 데이터를 붙일 때, **데이터 소스가 조용히 틀린 값을 주면
모델이 그걸 세탁해서 내보낸다.** 모델은 그 값을 의심할 근거가 없다.

## 재발 방지

- **날짜 구간 API 는 끝점의 포함 여부를 먼저 확인한다.** exclusive 가 흔하다
  (Cost Explorer, 많은 SQL `BETWEEN` 이 아닌 범위 질의, 파이썬 `range`).
  "오늘 하루"를 조회할 때 결과가 0 이면 이걸 먼저 의심한다.
- **경계값으로 테스트한다.** 이번 달(긴 구간)은 잘 되고 오늘(하루)만 안 됐다.
  구간이 길면 하루 차이가 안 보인다. **가장 짧은 구간**으로 확인해야 드러난다.
- **skill 의 기본값이 안전하게 동작하도록 만든다.** 모델이 인자를 안 넘겨도 맞는 답이 나와야 한다.
  모델에게 "end 는 exclusive 니까 +1 해라"를 프롬프트로 시키는 건 신뢰할 수 없다.
- **외부 데이터 소스는 skill 안에서 검증한다.** 값이 0/빈 배열/null 일 때
  "정말 0인가, 아니면 조회가 잘못됐나"를 구분할 수 있어야 한다.

## 같이 있던 것 — 비용을 묻는 데 비용이 든다 (#51)

Cost Explorer 는 **API 호출당 ~$0.01** 이다.

Agent Loop 가 도구를 여러 번 부를 수 있으므로, 비용 질문 한 번에 CE 를 5번 부르면 $0.05 다.
`MAX_TURN_STEPS`(=5) 가 상한을 만들고 실제로는 질문당 1~2회로 끝나는데,
**이건 우연히 안전한 것이지 설계로 막은 게 아니다.**
skill 호출 횟수에 별도 상한을 두지 않았다.

## 배운 점

**에러가 없는 게 더 나쁜 경우가 있다.** 예외가 났으면 바로 봤을 텐데,
정상 응답의 값이 0 이라 한참 지나서야 이상하다고 느꼈다.

**API 문서에서 "inclusive/exclusive"는 대충 읽고 넘어가는 부분이다.**
그리고 그 한 단어가 결과를 통째로 바꾼다.
[gym-management-db 트러블 03](../../gym-management-db/troubleshooting/03-GET-members-p95-2초.md) 에서
"그럴듯한 원인을 검증 없이 적으면 그게 기록으로 남는다"고 썼는데,
여기서는 **그럴듯한 가정을 검증 없이 코드에 넣었다.**

# 10. 스켈레톤을 먼저 커밋하고 구현은 다음 날

> 메모: 2026-06-30에 개요 문서 3개 + skip 처리된 테스트 뼈대 + 빈 스텁 함수를 커밋하고,
> 구현은 하나도 안 했다. 다음 작업일(07-01)에 그걸 순서대로 채웠다.

---

## 상황

이 프로젝트는 **한 번 앉으면 몰아치고 몇 주를 비우는** 리듬이다
(→ [타임라인](../타임라인.md)). 5주, 3주, 3주씩 끊긴다.

그래서 매번 돌아올 때마다 같은 비용을 치른다 —
**"이 저장소가 지금 어디까지 와 있고, 다음에 뭘 하려 했더라."**

3단계를 시작하며 개선 항목 9개를 정리했는데, 이걸 하루에 다 할 수 없다는 것이 분명했다.

## 결정

**개요와 뼈대를 먼저 커밋하고, 구현은 다음 작업일로 미룬다.**

`docs/upgrades/` 에 번호를 붙인 문서를 두고, 각 문서에 고정된 틀을 쓴다.

```
## 목표          왜 하는가
## 현재 동작      지금 코드가 어떻게 돼 있나 (실제 코드 인용)
## 구현 개요      무엇을 어떤 순서로
## 손대는 파일    - [ ] 체크박스
## 체크리스트     - [ ] 검증할 시나리오
## 면접 포인트    한 문장 요약
```

2026-06-30 커밋 5개가 전부 이것이다.

- `docs/upgrades/01,02,03` — 개요 문서만
- `tests/test_integration_moto.py` — **`@pytest.mark.skip` 이 붙은 뼈대**
- `lambda/register/handler.py` — `is_blocked_host()` **빈 스텁**

  ```python
  def is_blocked_host(url):
      # TODO(upgrade-05): 호스트 IP 해석 후 사설/루프백/링크로컬/예약 대역이면 True
      return False
  ```

다음 작업일(07-01) 커밋 5개가 그 5개를 순서대로 채운다.
문서의 체크박스가 `- [ ]` 에서 `- [x]` 로 바뀌는 것이 진행 기록이 된다.

## 왜

- **다시 앉았을 때 읽을 것이 있다.** 커밋 로그를 되짚는 대신 문서를 연다.
  [gym-management-db 트러블슈팅 README](../../gym-management-db/troubleshooting/README.md) 가
  *"당시 기록을 남기지 않아 커밋 로그에서 되짚어야 한다 — 기록을 미루면 이렇게 된다"* 라고
  적은 것에 대한 **다른 대응**이다.
- **"현재 동작"을 실제 코드로 적어 두면 판단 근거가 남는다.** 예를 들어 upgrade-01 문서는
  기존 알림 조건을 그대로 인용한다.

  ```python
  # 상태가 UP에서 DOWN으로 바뀔 때만 알림
  if previous_status != "DOWN" and status == "DOWN":
  ```

  이 두 줄이 나중에 [결정 04](04-알림-상태를-raw-status와-분리.md) 의 출발점이 됐다.
- **스텁이 자리를 표시한다.** 빈 함수라도 있으면 어디에 무엇이 들어갈지 코드에 남는다.
  `moto` 테스트를 `skip` 으로 넣어 둔 것도 같다 — 파일이 있으니 다음에 지우고 채우면 된다.
- **커밋이 작게 쪼개진다.** `docs(upgrade-03):` → `ci(upgrade-03):` 처럼
  같은 번호가 문서와 구현 두 커밋에 걸리므로, 나중에 하나를 찾으면 나머지가 따라온다.

## 왜 다른 건 안 썼나

**GitHub Issues 로 관리**

정석이고, 저장소 밖에서도 보인다. 대신 **코드와 같이 버전 관리되지 않는다.**
"그때 코드가 어땠는지"를 인용해 둔 문서는 `git log` 로 같이 따라온다.
그리고 이 프로젝트는 혼자 하는 학습 프로젝트라 이슈 트래커의 협업 기능이 필요 없었다.

**한 번에 다 구현하고 문서는 나중에**

지금까지 이렇게 했고, 그래서 [gym-management-db](../../gym-management-db/README.md) 는
5월에 겪은 것을 9월에 커밋 로그로 복원해야 했다.

**아무것도 안 남기고 다음에 다시 판단**

3주 뒤의 나는 3주 전의 맥락이 없다. 그때의 판단 근거(무엇을 봤고 왜 그렇게 하려 했는지)가
사라지면 **결정을 처음부터 다시 한다.**

## 이 방식의 대가

**문서가 코드보다 앞서 있으면, 안 한 것이 한 것처럼 보인다.**

upgrade-05 문서는 07-01 이후로 안 갱신됐고, `worker 재검증` 체크박스가
**빈칸으로 남아 있다** (→ [결정 07](07-SSRF를-등록-시점에-차단.md)).
로드맵 README 표의 상태는 `✅ 완료` 다. 항목 단위로는 완료가 맞지만
**세부 체크박스 하나가 안 닫힌 채 완료로 표시**돼 있다.

체크박스를 쓰기로 했으면 **닫히지 않은 칸을 완료 표시 위로 올려야** 한다.
지금은 문서를 열어야만 보인다.

## 배운 점

**계획을 커밋하면 계획도 리뷰 대상이 된다.**
머릿속에 있는 다음 단계는 검토할 수 없지만, 파일로 있으면 diff 로 보인다.
대신 **계획과 실제가 어긋났을 때 그것도 파일로 남는다** — 위의 빈 체크박스처럼.

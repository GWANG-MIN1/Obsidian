# 09. tfsec 은 soft-fail, ruff·fmt 만 하드 게이트로

> 메모: 품질 게이트를 넣으면서 **무엇이 배포를 막을 자격이 있는가**를 도구마다 다르게 정했다.
> upgrade-03, 2026-07-01 커밋 `188a505`

---

## 상황

이 시점의 CI 는 `pytest` 만 돌았다. 배포 전에 코드 스타일·IaC 포맷·IaC 보안을
검사하는 게이트를 넣기로 했다.

| 도구 | 대상 | 성격 |
|---|---|---|
| `ruff` | Python | 린트 — **답이 하나다** |
| `terraform fmt -check` | Terraform | 포맷 — **답이 하나다** |
| `tfsec` | Terraform | 보안 정적분석 — **판단이 필요하다** |

셋을 같은 강도로 걸 것인가.

## 결정

**앞의 둘은 실패하면 CI 를 멈추고, `tfsec` 은 경고만 남긴다.**

```yaml
- name: Ruff (lint + import order)
  run: ruff check .                                  # 실패 = 빨간불

- name: Terraform fmt check
  run: terraform fmt -check -recursive               # 실패 = 빨간불

- name: tfsec (IaC 보안 스캔, soft-fail)
  uses: aquasecurity/tfsec-action@v1.0.3
  with:
    working_directory: terraform
    soft_fail: true                                  # 실패해도 초록불
```

게이트를 통과시키려고 **기존 코드를 정리했다** — `report` import 정리, `lambda.tf` fmt,
E501(줄 길이). 게이트를 넣은 커밋과 코드를 고친 커밋이 같다.

## 왜

- **`ruff` 와 `fmt` 는 옳고 그름이 자명하다.** 통과 못 하면 고치면 되고, 고치는 데
  판단이 안 든다. 이런 검사는 **막아도 아무도 안 억울하다.**
- **`tfsec` 은 다르다.** "S3 버킷에 암호화가 없다", "SQS 에 KMS 키가 없다" 같은 경고가
  나오는데, 이 프로젝트에서 **의도적으로 안 한 것**들이 섞인다.
  전부 막으면 `#tfsec:ignore` 주석이 코드에 흩뿌려지고, 그러면 **무시가 기본값**이 된다.
- **"경고를 보되 막지는 않는다"를 명시적으로 골랐다.** 이게 타협이라는 걸 알고 골랐고,
  워크플로우 스텝 이름에 `soft-fail` 을 적어 뒀다.

## 왜 다른 건 안 썼나

**tfsec 도 하드 게이트로**

이상적이다. 그러려면 **모든 경고를 먼저 처리해야** 한다 — 고치거나, 무시 주석을 달거나.
그 작업 없이 켜면 CI 가 빨간불로 굳고, 결국
[결정 08](08-배포를-자동-push에서-수동-트리거로.md) 에서 없앤 문제를 다시 만든다.

**tfsec 을 아예 안 넣는다**

경고를 볼 기회 자체가 없어진다. soft-fail 이라도 **로그에 남고 PR 에서 보인다.**

**`checkov` 로 바꾼다**

규칙이 더 많고 더 시끄럽다. 하드 게이트로 못 걸 이유가 더 커진다.

## 이 결정의 대가 — 정직하게

**`tfsec` 은 지금 CI 를 하나도 막지 못한다.** 경고가 몇 건인지, 무엇인지,
그중 무엇을 고칠지 **한 번도 정리하지 않았다.**

저장소 README 는 CI 를 *"코드 품질 게이트"* 라고 부르고 tfsec 을
*"보안 스캔"* 으로 나열한다. 틀린 말은 아니지만, **읽는 사람은 그게 배포를 막는다고
읽을 가능성이 높다.** 그래서 이 노트와 [프로젝트 README](../README.md#숫자로-말할-것) 에
"경고가 있어도 초록불"이라고 적어 둔다.

*"검증이 있다"와 "검증이 작동한다" 사이의 간극* —
[projects/README](../../README.md) 가 두 프로젝트를 비교하며 쓴 문장이 여기에도 그대로 걸린다.
다만 이번엔 **모르고 그런 게 아니라 알고 고른 것**이라는 점이 다르다.

## 배운 점

**게이트를 넣는 것보다 게이트의 강도를 정하는 게 어렵다.**
전부 막으면 우회하게 되고, 전부 통과시키면 없는 것과 같다.
**어떤 검사가 배포를 막을 자격이 있는지**를 도구마다 따로 정해야 한다.

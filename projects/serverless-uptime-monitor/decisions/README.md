# Decisions

이 프로젝트에서 **무엇을 왜 그렇게 정했는가**의 기록.
형식과 원칙은 [`../../gym-management-db/decisions/README.md`](../../gym-management-db/decisions/README.md) 와 같다.

```
## 상황              무엇을 정해야 했는가
## 결정              무엇을 택했는가
## 왜                근거 — 확인한 사실 기준으로
## 왜 다른 건 안 썼나   버린 선택지와 그 이유
```

## 이 프로젝트에서 특히 남길 만한 것

- **04** 는 `status`(마지막 체크 결과)와 `alert_state`(확정된 알림 상태)를 **한 필드에서 두 필드로**
  쪼갠 결정이다. 이 프로젝트에서 가장 잘 나온 설계이고, 하위호환 처리까지 같이 들어 있다.
- **05 · 06** 은 짝이다. "정상을 능동적으로 증명한다"(05)와 "무엇을 근거로 정상이라 하는가"(06).
  06 이 없으면 05 는 **얼어붙은 `UP` 을 그대로 정상이라고 보고**한다.
- **08 · 09** 는 *"게이트가 있다"* 와 *"게이트가 막는다"* 사이에서 의도적으로 약한 쪽을 고른 것들이다.
  타협한 이유를 적어 두는 것이 목적이다.

## 저장소 문서와의 관계

`docs/upgrades/01~09` 에 이미 "무엇을 왜 하려 했는가"가 있다. 여기는 그걸 옮겨 적지 않고
**버린 선택지**와 **저장소 문서가 안 적은 대가**만 적는다.

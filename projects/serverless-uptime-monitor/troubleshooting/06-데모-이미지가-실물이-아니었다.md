# 06. 데모 이미지가 실물이 아니었다

- **발생**: 2026-07-30 (목업 SVG 로 문서 작성) → 2026-07-31 (`-> 검증 필요` 메모) → 2026-08-01 (교체)
- **증상 한 줄**: README 의 알림 스크린샷이 **실제로 발송된 화면이 아니라 형식 설명용 그림**이었다

---

## 현상

[요약 알림](../decisions/05-요약-알림을-기존-알림-큐에-얹기.md)을 구현하면서 README Demo 섹션에
`summary-alert.svg` 를 넣었다. **손으로 그린 목업**이다. 메시지가 어떤 모양으로 나가는지
설명하기엔 충분하고, **실제로 그렇게 나가는지는 증명하지 않는다.**

같은 종류의 어긋남이 하나 더 있었다. `endpoints-up.svg` 에 **API Gateway 주소가 박혀 있었는데**,
스택을 재배포하면서 API ID 가 바뀌어 **그 주소는 더 이상 존재하지 않았다.**

## 환경

- 저장소 README 의 Demo 섹션 (`docs/*.svg`, `docs/*.png`)
- 배포 후 실제 Slack/SNS 발송을 확인하기 전 단계

## 진단

### 1) 목업과 실물의 차이를 문서가 구분하지 않는다

README 를 읽는 사람은 `![Summary Alert](docs/summary-alert.svg)` 를 보고
**"실제로 이렇게 온다"** 고 읽는다. 파일 확장자가 SVG 인 것만으로는 목업인지 알 수 없다.

이 프로젝트는 [요약 알림이 실제로 발송되는 것](01-헬스체크가-조용히-멈췄다.md)을
아직 확인하기 전이었다. **구현했다 ≠ 동작을 봤다.**

### 2) 그래서 커밋으로 표시를 남겼다

2026-07-31, 커밋 하나가 README 에 **한 줄만** 추가한다.

```diff
 위 스크린샷은 `https://httpbin.org/status/500` 을 일부러 등록해 장애를 재현한 것입니다.

+-> 검증 필요
 </details>
```

코드가 아니라 **"아직 확인 안 했다"는 표시**다. 다음에 열었을 때 잊지 않기 위한 것.
이 프로젝트는 몇 주씩 끊기는 리듬이라([타임라인](../타임라인.md)) 이런 표시가 실제로 필요하다.

### 3) 이미지에 박힌 값은 인프라와 함께 늙는다

SVG 안의 API 주소는 **텍스트지만 검색되지 않는다.** `grep` 으로 옛 주소를 찾아도
이미지 파일은 잘 안 걸리고, 링크 검사 도구도 이미지 내부는 안 본다.
스택을 재배포하면 API Gateway ID 가 바뀌는데 **문서가 그걸 따라갈 방법이 없다.**

## 원인

- 문서를 **구현과 같은 커밋에** 썼고, 그 시점에는 보여줄 실물이 없었다
- 이미지에 **환경에 따라 바뀌는 값**(API 주소)을 박아 넣었다

## 해결

2026-08-01, 배포하고 실제로 받은 화면으로 전부 교체했다.

| 파일 | 무엇 |
|---|---|
| `summary-alert.jpg` | 정상(초록) — `All 3 endpoints UP` |
| `summary-stale-alert.jpg` | 이상 감지(노랑) — `2/3 UP, 1 stale` |
| `summary-email-alert.png` | 같은 요약의 SNS 이메일 |

목업 `summary-alert.svg` 는 삭제. `endpoints-up.svg` 의 API 주소는 새 주소로 갱신.
`-> 검증 필요` 는 목적을 다했으므로 제거.

**두 번째 스크린샷이 이 프로젝트에서 제일 값진 이미지가 됐다.**
연출이 아니라 [실제로 잡아낸 장애](01-헬스체크가-조용히-멈췄다.md)의 화면이라,
*"왜 `UP` 상태값만 믿으면 안 되는가"* 의 근거로 그대로 쓰인다.
README 도 그 점을 명시한다 — *"이건 연출이 아니라 실제 프로덕션에서 잡아낸 장애입니다."*

정리하면서 중복도 걷어냈다. 이메일 스크린샷 두 장 중 하나를 지우면서
**`SUMMARY` 와 `DOWN` 은 다른 사건**이라는 것을 커밋 메시지에 적어 뒀다 —
`stale` 은 "모니터가 멈춤", `DOWN` 은 "감시 대상이 죽음". 요약 알림 3장이
장애 알림 스크린샷을 대체하지 못한다.

## 재발 방지

- **목업은 "목업"이라고 적거나, 아예 안 넣는다.** 실물이 없으면 그 자리를 비워 두는 게 낫다.
- **확인 안 한 것에 표시를 남긴다.** `-> 검증 필요` 한 줄이 실제로 작동했다 —
  다음에 열었을 때 무엇을 확인해야 하는지가 문서 안에 있었다.
- **이미지에 환경별 값을 박지 않는다.** API 주소는 `{api-id}` 같은 플레이스홀더로 두거나
  아예 자른다. 저장소 README 의 `curl` 예시는 이미 `https://{api-id}.execute-api...` 형태다 —
  **텍스트는 그렇게 해 놓고 이미지에는 실주소를 넣었다.**

## 배운 점

**"구현했다"와 "동작하는 것을 봤다"는 다른 사건이고, 문서는 둘을 구분해서 적어야 한다.**
이 프로젝트가 [aws-serverless-agent](../../aws-serverless-agent/README.md) 와 갈리는 지점이기도 하다 —
저쪽은 검증 스크린샷 50장을 남겼지만 자동 테스트가 0이고, 이쪽은 테스트 78개를 두고도
**실제 발송 화면은 마지막 날에야 봤다.**

**목업으로 시작해서 실물로 끝내는 순서 자체는 나쁘지 않다.** 문제는 그 사이에
목업이 실물인 척하는 구간이 생기는 것이고, `-> 검증 필요` 는 그 구간을 **표시하는** 방법이었다.

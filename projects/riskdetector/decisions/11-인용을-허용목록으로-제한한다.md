# 11. 인용을 허용목록으로 제한하고, 일부 답변은 LLM 을 안 쓴다

> 메모: *"손해배상 배수 등 입력 데이터에 없는 수치를 모델이 임의 생성"* — 커밋 `88f0332` 본문.
> 프롬프트로 막고, 목록으로 좁히고, 그래도 안 되는 건 사전으로 대체했다. 2026-05-21

---

## 상황

챗봇을 붙이고 바로 드러난 문제를 커밋 메시지에 그대로 적어 뒀다.

> - 선택한 조항을 바꿔도 직전 답변과 같은 내용 반환
> - **손해배상 배수 등 입력 데이터에 없는 수치를 모델이 임의 생성**
> - 계약/법률 무관 질문(짜장면 레시피 등)도 친절히 답함
> - "쉽게 설명해줘"를 무시하고 동일한 난이도로 응답
> - "민법 제623조 — 임대인의 의무" 인용 카드가 모든 응답에 하드코딩

두 번째가 제일 위험했다. **계약서 도메인에서 조작된 판례 번호는 서비스를 해롭게 만든다.**
"2002다65401 판례에 따르면 안전합니다"를 믿고 계약하면 그 피해는 실재한다.

## 결정

**세 겹으로 막았다. 층마다 자유도가 줄어든다.**

### 1겹 — 프롬프트 절대 규칙

```
3. **환각 금지 & 법령 정확성** (← 가장 중요):
   - 분석 데이터·KB에 없는 **판례 번호는 절대 만들어내지 마세요**. 손해배상 배수·금액·기간 등
     구체적 수치도 데이터에 명시된 값만 사용합니다.
   - 법령 조문을 인용할 때는 **실제로 존재하는 조문**을 **실제 내용에 맞게** 인용하세요.
     조문 번호 또는 내용이 조금이라도 불확실하면 번호를 적지 말고
     "관련 법령상 일반 원칙은…" 식으로 풀어서 설명하세요.
     **잘못된 조문 번호·내용은 거절보다 더 큰 문제입니다.**
4. **수치 보수성**: … 추정·예시·관행 수치 생성 금지.
```

`temperature` 도 **0.4 → 0.2** 로 내렸다.

### 2겹 — 인용 허용목록 (citation whitelist)

분석 데이터와 KB 검색 결과에서 **정규식으로 실제 등장한 인용만 뽑아** 프롬프트에 목록으로 준다.

```ts
const CITATION_REGEX = /(민법|상법|형법|근로기준법|저작권법|주택임대차보호법|상가건물\s*임대차보호법)\s*제\s*\d+\s*조(?:\s*제\s*\d+\s*항)?|\d{4}\s*[다가나허누]\s*\d+/g;

function collectAllowedCitations(req: ChatRequest, retrieved: RetrievedItem[]): string[] {
  const refs = new Set<string>();
  add(req.selectedToxic?.reasonReference);
  add(req.selectedToxic?.reason);
  (req.allToxics ?? []).forEach((t) => { add(t.reasonReference); add(t.reason); });
  retrieved.forEach((item) => { add(item.sourceLabel); add(item.basisPhrase); add(item.text); });
  return Array.from(refs);
}
```

그리고 **판례와 법령의 자유도를 다르게** 줬다.

> 그 외 법령은 **조문 번호와 내용이 100% 확실한 주요 법령(민법·근로기준법·주택임대차보호법 등)에
> 한해** 인용 가능합니다. … **판례 번호는 위 목록에 있는 것만 사용 — 외부 판례 번호 생성 금지.**

### 3겹 — LLM 을 아예 안 쓰는 경로

특정 법령을 직접 물으면 **모델을 호출하지 않고** 미리 쓴 문장을 돌려준다.

```ts
const KNOWN_LAW_CONTEXT: Record<string, string> = {
  '민법 제623조': '임대인은 임차인이 목적물을 사용·수익할 수 있도록 넘겨주고, …',
  '민법 제398조': '계약에서 손해배상액을 미리 정할 수 있지만, 예정액이 부당하게 과다하면 …',
  '민법 제103조': '선량한 풍속이나 사회질서에 반하는 법률행위는 무효가 된다는 조항입니다.',
  '민법 제104조': '…', '근로기준법 제17조': '…', '저작권법 제45조': '…',
  '주택임대차보호법 제7조': '…',
};

// POST 핸들러 — LLM 호출 전에 가로챈다
const directLawAnswer = requestedLawRef ? buildDirectLawAnswer(requestedLawRef, body.selectedToxic) : null;
if (directLawAnswer) {
  return new Response(directLawAnswer, { headers: { 'Content-Type': 'text/plain; charset=utf-8' } });
}
```

## 왜

- **판례 번호는 검증이 불가능하다.** 법령 조문은 사람이 눈으로 틀린 걸 알아볼 수 있지만,
  `2002다65401` 같은 사건번호는 **그럴듯하면 구분이 안 된다.** 그래서 판례만 허용목록을
  **절대 조건**으로, 법령은 *"100% 확실하면"* 으로 완화했다.
- **조문 7개를 하드코딩한 이유**: 이 서비스가 다루는 계약 유형(임대차·근로·전속)에서
  실제로 반복 등장하는 조문이 그만큼이었다. **가장 자주 나오는 답을 가장 확실하게** 만들었다.
  LLM 호출도 안 하니 지연도 0이고 비용도 0이다.
- **`temperature` 0.2 는 창의성을 버린 값**이다. 계약서 설명에 창의성은 필요 없다.

## 왜 다른 건 안 썼나

**출력 후 검증 (응답에서 인용을 추출해 목록과 대조하고, 위반이면 버리기)**

이게 제일 확실하다. 프롬프트는 **부탁**이고 후처리는 **강제**다.
안 한 이유가 명확하다 — **스트리밍 때문이다.** 토큰을 흘려보내는 중에는
전체 응답을 볼 수 없고, 다 받아서 검증하면 스트리밍이 아니다.
→ [결정 12](12-검증이-필요한-답변은-스트리밍을-포기했다.md) 에서 **일부 경로만** 이 길을 갔다.

**RAG 결과에 없으면 무조건 거절**

가장 안전하고, 실제로 한때 이렇게 했다. **그래서 정상 질문까지 막혔다.**
→ [트러블 02](../troubleshooting/02-환각을-막으려고-정상-질문까지-막았다.md)

**법령 전문을 전부 프롬프트에 넣기**

컨텍스트 한도와 비용 문제. 그리고 KB 검색이 있는데 전문을 넣으면 RAG 를 쓰는 의미가 없다.

**파인튜닝**

데이터도 시간도 없었고, 파인튜닝은 환각을 줄이는 수단이 아니라 **말투를 바꾸는 수단**이다.

## 결과

**막는 데는 성공했고, 막는 김에 정상 질문도 막았다.** 그 왕복이
[트러블 02](../troubleshooting/02-환각을-막으려고-정상-질문까지-막았다.md) 다.

그리고 세 겹 사이에 **구멍 하나**가 있다.
KB 검색이 실패해 `retrieved` 가 비면 허용목록이 얇아지고, 프롬프트는 이렇게 바뀐다.

```ts
: '\n\n## 인용 가능한 법령·판례\n분석 데이터에서 명시된 법령·판례는 없습니다.
   조문 번호와 내용이 100% 확실한 주요 법령(민법·근로기준법·주택임대차보호법 등)은
   인용해도 되지만, …'
```

**검색이 실패하면 가드레일이 느슨해진다.** 그런데 검색 실패는 `catch { return [] }` 로
조용히 넘어가므로([트러블 02](../troubleshooting/02-환각을-막으려고-정상-질문까지-막았다.md)),
*"지금 가드레일이 느슨한 상태"* 를 아무도 모른다.

`KNOWN_LAW_CONTEXT` 의 7개 문장도 **내가 손으로 쓴 요약**이다. 법령 원문 대조를
누가 했는지 기록이 없다. 조문 번호를 모델이 틀리는 걸 막으려고 만든 장치가
**사람이 틀릴 수 있는 장치**로 바뀐 셈이다.

## 배운 점

**환각을 막는 가장 확실한 방법은 그 답을 LLM 이 만들지 않게 하는 것이다.**
세 겹 중 실제로 100% 확실한 건 3겹(사전 답변)뿐이다. 1겹은 부탁이고 2겹은 힌트다.
**자주 나오는 질문일수록 결정론적으로 답하는 게 옳다** — LLM 은 나머지를 맡는다.

**그리고 가드레일의 강도가 런타임 상태에 따라 변하면 안 된다.**
검색이 되면 조이고 안 되면 푸는 구조는, 정확히 **가장 근거가 없을 때 가장 느슨해진다.**

# 12. 검증이 필요한 답변은 스트리밍을 포기했다

> 메모: "쉽게 설명해줘" 경로만 `stream: false` 다.
> 답을 검사하려면 답이 다 나와 있어야 하고, 다 나와 있으면 스트리밍이 아니다. 2026-05-21

---

## 상황

챗봇의 기본 동작은 **스트리밍**이다. 토큰이 오는 대로 브라우저에 흘려보낸다.

```ts
const readable = new ReadableStream({
  async start(controller) {
    for await (const chunk of stream) {
      const delta = chunk.choices[0]?.delta?.content;
      if (delta) controller.enqueue(encoder.encode(delta));
    }
    controller.close();
  },
});
```

그런데 **"쉽게 설명해줘"** 모드에는 추가 요구가 있었다.
모델이 범위 제한 규칙에 걸려 *거절 문구*를 내보낼 때가 있는데, 이 모드에서는
**거절하면 안 된다** — 사용자가 선택한 조항이 눈앞에 있고, 그걸 쉽게 설명해 달라는 건
정당한 요청이다. → [트러블 02](../troubleshooting/02-환각을-막으려고-정상-질문까지-막았다.md)

즉 **응답을 보고 "거절이면 갈아치우는" 후처리**가 필요했다.
그런데 스트리밍은 첫 토큰이 이미 사용자 화면에 찍힌 뒤다. **되돌릴 수 없다.**

## 결정

**쉬운 모드에서만 스트리밍을 끄고, 응답을 검사한 뒤 통째로 돌려준다.**

```ts
if (easyMode && body.selectedToxic) {
  const fallback = buildDirectEasyAnswer(body.selectedToxic);   // ← LLM 없이 만든 대체 답
  try {
    const completion = await createChatCompletionWithRetry(openai, {
      model: 'gpt-4o-mini',
      messages,
      stream: false,            // ← 여기만 false
      max_tokens: 400,
      temperature: 0.2,
    });
    const answer = completion.choices[0]?.message?.content?.trim() ?? '';
    return new Response(answer && !isOutOfScopeAnswer(answer) ? answer : fallback, { ... });
  } catch (error) {
    if (fallback) return new Response(fallback, { ... });   // 호출 실패도 대체 답으로
    ...
  }
}
```

검사는 문자열 일치 한 줄이다.

```ts
function isOutOfScopeAnswer(answer: string): boolean {
  return answer.trim() === OUT_OF_SCOPE_MESSAGE;
}
```

대체 답은 **분석 결과 필드를 문장 틀에 끼운 것** — LLM 을 안 쓴다.

```ts
function buildDirectEasyAnswer(selectedToxic?: ToxicSlim): string | null {
  const lines = [
    `${title}은 계약 한쪽에게 부담이 크게 몰릴 수 있는 조항이에요.`,
    reason ? `쉽게 말하면 ${reason}` : …,
    suggestion ? `그래서 ${suggestion}` : '그래서 조건과 예외를 더 구체적으로 적는 게 좋아요.',
  ];
  return lines.join('\n');
}
```

## 왜

- **스트리밍과 출력 검증은 양립하지 않는다.** 검증하려면 전체가 있어야 하고,
  전체가 있으면 흘려보낼 게 없다. 중간에 끊고 교체하는 방법(첫 문장만 보고 판단)도 있지만
  **거절 문구가 정확히 한 문장이라 판단 시점이 곧 끝**이다.
- **쉬운 모드는 응답이 짧다.** 프롬프트가 *"한 문장 50자 내외, 전체 4문장 이내"* 를 요구하고
  `max_tokens: 400` 이다. **스트리밍의 이득이 가장 작은 경로**라 포기 비용이 낮았다.
- **거절이 가장 많이 나오는 경로였다.** "쉽게 설명해줘"는 짧고 지시대명사가 없어서
  모델이 범위를 못 잡는다. 검증이 가장 필요한 곳에 검증을 붙였다.
- **대체 답이 성립하는 경로였다.** 쉬운 모드는 `selectedToxic` 이 있을 때만 타므로
  `title` · `reason` · `suggestion` 이 이미 손에 있다. **문장 틀에 끼우면 답이 된다.**
  일반 질문은 이게 불가능하다 — 무슨 질문인지 모르니 틀을 만들 수 없다.

## 왜 다른 건 안 썼나

**전 경로를 비스트리밍으로 통일**

일관성은 좋아지지만 **챗봇의 핵심 UX 를 버린다.** 긴 답변이 8~10초 뒤 한 번에 뜨면
"멈춘 것"처럼 보인다. 스트리밍을 쓰려고 OpenAI 를 고른 것인데
([결정 10](10-챗봇만-OpenAI로-분석은-Bedrock으로.md)) 그걸 다 끄면 선택 이유가 사라진다.

**스트리밍하면서 거절을 감지하면 중단하고 대체 답으로 교체**

기술적으로는 가능하다(`controller.enqueue` 를 멈추고 새 텍스트를 밀어넣기).
하지만 **사용자 화면에 이미 찍힌 글자를 지우는** UX 가 된다. 답변이 깜빡이며 바뀐다.
거절 문구가 짧아서 거의 전체가 이미 나가 있을 것이다.

**프롬프트만 더 강하게 써서 거절을 없애기**

실제로 그 방향으로 여러 번 갔다 — *"너무 까다롭게 거절하지 마세요"*,
*"KB 검색 결과가 비어 있어도 거절하지 말고"* 같은 문구가 프롬프트에 쌓여 있다.
**프롬프트는 확률을 줄이고 0으로 만들지 않는다.** 그래서 코드로 막는 층이 필요했다.

**클라이언트에서 거절을 감지해 재요청**

왕복이 두 번이 되고, 두 번째도 거절할 수 있다.

## 결과

**한 라우트에 응답 형태가 두 개가 됐다.**

| 경로 | 응답 | 검증 |
|---|---|---|
| 특정 법령 질문 | `text/plain` 즉시 (LLM 미호출) | 불필요 — 사전에서 꺼낸 문장 |
| 쉬운 모드 + 선택 조항 | `text/plain` 일괄 | **있음** (거절이면 대체) |
| 그 외 | `text/plain` 스트림 | 없음 |

셋 다 `Content-Type: text/plain; charset=utf-8` 이라 **클라이언트는 구분하지 않아도 된다** —
스트림이든 일괄이든 텍스트를 읽으면 된다. 이건 잘 나온 부분이다.

대신 **`OUT_OF_SCOPE_MESSAGE` 문자열이 계약이 됐다.**
거절 감지가 `answer.trim() === OUT_OF_SCOPE_MESSAGE` 라서, 프롬프트의 그 문구를
한 글자만 바꾸면 **검증이 조용히 무력화**된다. 프롬프트에 *"정확히 `…` 라고만 답하세요
(다른 부연 설명 X)"* 로 적어 둔 게 그 때문이다. **모델이 문구를 한 글자라도 바꾸면 통과한다.**

관련해서, 과거 거절 답변이 히스토리에 남으면 모델이 **자기 거절을 따라한다**는 것도 발견해서
히스토리에서 걷어낸다.

```ts
function stripOutOfScopeHistory(messages: ChatRequest['messages']) {
  return messages.filter((message) => {
    if (message.role !== 'assistant') return true;
    return message.content.trim() !== OUT_OF_SCOPE_MESSAGE;
  });
}
```

## 배운 점

**출력을 검증하려면 스트리밍을 포기해야 한다 — 그러니 검증이 필요한 경로만 골라 포기한다.**
전부 스트리밍하거나 전부 검증하는 것 사이에 **경로별로 나누는** 선택지가 있었고,
그게 이 프로젝트에서 가장 잘 나온 판단이었다.

**그리고 문자열 동일성으로 모델 출력을 판정하는 건 깨지기 쉬운 계약이다.**
프롬프트의 문구와 코드의 상수가 **한 글자라도 어긋나면** 검증이 사라진다.
지금은 같은 파일 안에 있어서 유지되지만, 그걸 보장하는 테스트는 없다
(이 저장소의 자동 테스트는 1개다).

의 *"같은 파일 안의 일관성은 검사되지 않는다"* 와 같은 종류의 취약점이다.

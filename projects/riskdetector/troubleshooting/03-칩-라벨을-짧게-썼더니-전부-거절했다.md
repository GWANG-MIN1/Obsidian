# 03. 칩 라벨을 짧게 썼더니 모델이 전부 거절했다

- **발생**: 2026-05-22 · 커밋 `43741c6`
- **증상 한 줄**: 추천 질문 버튼을 누르면 특정 환경에서 **모든 답변이 범위 밖 거절**로 돌아왔다

---

## 현상

챗봇 하단에 추천 질문 칩(chip)을 뒀다. 라벨은 짧게 썼다.

```
[복사하기]  [집주인에게 메시지]  [비슷한 판례]
```

칩을 누르면 그 라벨이 **그대로 사용자 메시지로 전송**된다. 그리고 돌아온 답이 이것뿐이었다.

```
저는 계약서 위험 분석을 도와드리는 아르디예요. 계약 조항에 대해 궁금한 점을 물어봐 주세요!
```

커밋 본문이 증상을 이렇게 적었다.

> 칩 라벨이 단문("복사하기", "집주인에게 메시지", "비슷한 판례")이라
> 모델이 의도 추측 실패 → **over-rejection (특정 환경에서 모든 답변이 scope-guard
> 거절로 반환되는 현상)**

## 환경

- `gpt-4o-mini` · `temperature: 0.2`
- 시스템 프롬프트에 범위 제한 규칙이 걸린 상태
  ([결정 11](../decisions/11-인용을-허용목록으로-제한한다.md), 하루 전 `88f0332` 로 도입)
- 칩 라벨이 곧 user 메시지 내용

## 진단

### 1) 첫 의심 — 범위 규칙이 너무 세다 (부분 원인)

하루 전에 절대 규칙 5개를 넣었으니 그쪽을 의심하는 게 자연스러웠다.
실제로 그 규칙이 조건이긴 했다 — 규칙 1이 *"계약·법률과 완전히 무관한 주제는 거절"* 이었다.

하지만 **정상 문장으로 물으면 답했다.** "이 조항 왜 위험해?"는 통과했다.
규칙만이 원인이면 그것도 막혔을 것이다.

### 2) 칩과 직접 입력의 차이를 본다 → 문장 길이다

| 입력 | 결과 |
|---|---|
| `비슷한 판례` | **거절** |
| `비슷한 판례는 뭐가 있어?` | 답변 |
| `복사하기` | **거절** |
| `이 조항 왜 위험해?` | 답변 |

**같은 주제인데 어미와 물음표 유무로 갈렸다.**

### 3) 왜 그런가 — 명사구는 "질문"으로 해석되지 않는다

`복사하기` 는 문장이 아니라 **UI 동작의 이름**이다. 모델 입장에서 이건
계약서에 대한 질문이 아니고, 규칙 1의 *"다른 사이트 이용법"* 쪽에 가깝다.
`비슷한 판례` 는 주제어일 뿐 요청이 아니다.

그리고 규칙에 *"짧고 지시대명사가 없는 질문은 현재 선택 조항을 가리킨다"* 는 항목을
넣은 것은 **이 사건 이후**다. 그때는 짧은 입력을 해석할 근거가 프롬프트에 없었다.

### 4) 부수 원인 — 진입점이 FAB 이라 조항 컨텍스트가 없었다

같은 커밋이 다른 문제도 같이 고친다.

> 글로벌 FAB은 조항 선택 없이도 챗봇을 열어 **selectedToxic 누락** 사례 발생

`selectedToxic` 이 없으면 프롬프트가 이렇게 들어간다.

```
## 현재 선택된 조항 없음 — 사용자에게 좌측에서 조항을 먼저 선택하라고 안내하세요.
```

**짧은 칩 라벨 + 선택 조항 없음** 이 겹치면 모델이 답할 근거가 하나도 없다.
거절이 사실 합리적인 동작이었다.

## 원인

**UI 문자열이 곧 모델 입력이라는 걸 설계에 반영하지 않았다.**

칩 라벨은 **사람이 읽을 버튼 이름**으로 썼다. 짧고 명확한 게 UI 의 미덕이다.
그런데 그 문자열이 그대로 LLM 에 들어가는 구조였고, LLM 에게는
**짧은 명사구가 가장 해석하기 어려운 입력**이다.

거기에 진입점(FAB)이 조항 컨텍스트 없이 챗봇을 열 수 있었던 것이 겹쳤다.

## 해결

**세 가지를 같이 바꿨다.**

**(1) 칩을 자연어 풀문장으로**

```ts
// 두 곳이 같은 데이터를 쓴다 (SUGGESTED_QUESTIONS · COMPOSER_CHIPS)
"비슷한 판례는 뭐가 있어?"
"쉽게 설명해줄 수 있어?"
```

하드코딩된 임대차 전용 문구(`"집주인에게 메시지"`)는 제거했다.
**계약 유형에 따라 틀린 말이 되는 라벨**이었다.

**(2) 진입점을 조항 컨텍스트 CTA 로 이동**

```
변경 전  화면 우하단 FAB → 조항 선택 없이도 열림
변경 후  조항 상세 패널의 "아르디에게 물어보세요" CTA → 이 경로로만 열림
```

`ArdiChatbot` 의 `open` 상태를 부모(`result/page.tsx`)로 올리고,
`createPortal` 에는 오버레이만 마운트했다. FAB 블록은 삭제했다.
**챗봇이 항상 `selectedToxic` 과 함께 열린다.**

**(3) 프롬프트에 짧은 질문 해석 규칙 추가** (이후 커밋에서)

```
**중요**: 현재 선택된 조항이 있고 사용자가 "쉽게 설명", "왜 위험해", "어떻게 바꿔",
"이거 뭐야"처럼 짧게 물으면 무조건 (a)에 해당합니다.
```

커밋 본문이 결과를 이렇게 적었다.

> - 칩이 자연어 풀문장이라 **over-rejection 자동 해소.**
> - 챗봇이 항상 selectedToxic 컨텍스트와 함께 열려 조항별 답변 보장.

## 재발 방지

- **모델에 들어가는 문자열과 사람이 보는 문자열을 분리한다.** 칩에
  `{ label: "비슷한 판례", prompt: "비슷한 판례는 뭐가 있어?" }` 처럼 두 필드를 두면
  UI 는 짧게, 모델 입력은 완전하게 할 수 있다. **지금 코드는 여전히 한 문자열이다** —
  풀문장으로 바꿨을 뿐 구조는 안 바꿨다.
- **거절을 로그로 센다.** 거절률을 재는 장치가 없어서 *"특정 환경에서"* 라는 애매한
  표현으로 기록됐다. 어떤 입력이 얼마나 거절됐는지 집계했으면 원인이 즉시 보였을 것이다.
- **LLM 에 들어가는 모든 입력 경로를 목록으로 만든다.** 이 프로젝트에서 모델 입력은
  (가) 사용자 타이핑, (나) **칩 라벨**, (다) 분석 결과 필드, (라) KB 발췌문, (마) 조항 전환 마커
  — **다섯 곳**이다. (나)를 입력으로 세지 않은 게 이 사건이다.

## 배운 점

**LLM 을 넣으면 UI 문자열이 API 파라미터가 된다.**
버튼 이름을 바꾸는 건 보통 디자인 변경인데, 여기선 **백엔드 동작을 바꾸는 변경**이었다.
`"비슷한 판례"` → `"비슷한 판례는 뭐가 있어?"` 는 코드 로직을 한 줄도 안 건드리고
거절률을 바꿨다.

**그리고 잘 만든 UI 가 모델에게는 나쁜 입력일 수 있다.**
짧고 군더더기 없는 라벨은 UI 의 정석이고, 어미·물음표가 붙은 문장은 버튼으로는 어색하다.
**두 요구가 충돌하는데 한 문자열로 둘을 다 만족시키려 한 것**이 근본 실수다.
두 필드로 나누는 게 맞았고, 그건 지금도 안 고쳐져 있다.

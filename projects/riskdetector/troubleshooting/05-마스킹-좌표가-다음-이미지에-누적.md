# 05. 마스킹 좌표가 다음 이미지에 누적됐다

- **발생**: 2026-05-18 · 커밋 `6e8c074` (그리고 같은 diff 가 `206dcf2` 로 한 번 더)
- **증상 한 줄**: 이미지를 여러 장 올려 차례로 가리면, 2번째 이미지에 1번째의 검은 박스가 같이 그려졌다

---

## 현상

계약서 사진을 여러 장 올리면 페이지마다 마스킹 화면이 순서대로 뜬다.
1장에서 주민번호 부분을 가리고 다음으로 넘어가면,
**2장에도 같은 위치에 검은 박스가 이미 그려져 있었다.**

장을 넘길수록 박스가 쌓였다. 3장째에는 1·2장에서 그린 것이 다 얹혀 있다.
개인정보를 가리려고 만든 기능이 **엉뚱한 부분을 가리고, 가려야 할 부분은 놓치는** 상태였다.

## 환경

- `frontend/riskdetector-web/src/components/MaskingCanvas.tsx` — `imageFile` prop 하나를 받는 컴포넌트
- `frontend/riskdetector-web/src/app/upload/page.tsx` — `preparedFiles` 배열을 들고 인덱스를 넘긴다
- 이미지 전환이 **같은 컴포넌트에 prop 만 바꿔서** 일어난다 (언마운트 없음)

## 진단

### 1) 마스크 상태가 컴포넌트에 남아 있다

`MaskingCanvas` 는 사용자가 드래그한 영역을 `masks` state 에 배열로 쌓는다.
새 이미지로 넘어갈 때 **부모가 `imageFile` prop 만 바꾼다.**

React 는 같은 위치·같은 타입의 컴포넌트면 **언마운트하지 않는다.**
prop 만 바뀌고 **state 는 그대로 살아 있다.**

```
1장: masks = [{x:10,y:20,w:80,h:14}]
2장: imageFile 만 교체 → masks 는 여전히 [{x:10,y:20,...}]
     → 캔버스를 새로 그리면서 옛 masks 를 그대로 덮어 칠한다
```

### 2) 이미지 로드 `useEffect` 는 이미 있었다

`imageFile` 이 바뀔 때 캔버스를 다시 그리는 `useEffect` 는 있었다.
**이미지는 제대로 교체됐다.** 안 지워진 건 마스크 좌표뿐이다.
그래서 "이미지는 2장인데 박스는 1장 것"이라는 증상이 됐다.

### 3) 부모 쪽 배열 수정 방식도 의심했다 (원인은 아니었음)

```ts
const updated = [...preparedFiles];
updated[currentMaskingIdx] = maskedFile;
setPreparedFiles(updated);
```

복사 후 인덱스 대입이다. 얕은 복사를 하고 새 배열을 넣으니 **동작은 맞다.**
이게 원인은 아니었지만 같은 커밋에서 같이 바꿨다.

## 원인

**파생 상태를 prop 변경 시 초기화하지 않았다.**

`masks` 는 `imageFile` 에 종속된 값이다. "이 이미지에 대한 마스크"이지
"이 컴포넌트의 마스크"가 아니다. 그런데 생명주기가 **컴포넌트에 묶여** 있었다.

커밋 메시지가 그대로 적고 있다.

> MaskingCanvas: imageFile 변경 시 masks 상태 초기화 누락으로
> 이전 이미지의 마스크 좌표가 다음 이미지에 누적 적용되는 버그 수정

## 해결

이미지 로드 `useEffect` 맨 앞에 한 줄.

```ts
useEffect(() => {
    setMasks([]); // 새 이미지로 전환할 때 이전 마스크 좌표 초기화
    const img = new Image();
    const url = URL.createObjectURL(imageFile);
    img.src = url;
    ...
```

부모 쪽도 의도가 드러나게 고쳤다.

```diff
-    const updated = [...preparedFiles];
-    updated[currentMaskingIdx] = maskedFile;
+    const updated = preparedFiles.map((f, i) => (i === currentMaskingIdx ? maskedFile : f));
     setPreparedFiles(updated);
```

**같은 diff 가 두 커밋으로 들어갔다** (`6e8c074`, `206dcf2` — 내용·시각 동일).
브랜치를 파서 PR 로 올리는 흐름에서 나온 중복이고, 이 저장소에는 병합 커밋이 144개다.

## 재발 방지

- **`key` 로 컴포넌트를 강제 재생성하는 게 더 안전하다.**
  ```tsx
  <MaskingCanvas key={currentMaskingIdx} imageFile={preparedFiles[currentMaskingIdx]} ... />
  ```
  `key` 가 바뀌면 React 가 언마운트 후 새로 만든다. **state 초기화를 잊을 수 없는 구조**가 된다.
  지금 코드는 `setMasks([])` 를 **사람이 기억해야** 유지된다.
- **파생 상태는 state 로 두지 않는다.** 마스크를 `Record<index, Mask[]>` 로 부모가 들고
  자식에 내려주면 초기화 문제가 아예 없다. 그러면 "이전 장으로 돌아가기"도 공짜로 된다.
- **개인정보를 다루는 기능은 눈으로 확인한다.** 이건 캔버스에 **보이는** 버그였다.
  2장 이상으로 한 번만 눌러 봤으면 즉시 보였다. 한 장으로만 테스트한 게 원인이다.

## 배운 점

**React 에서 "다음 항목으로 넘어간다"는 prop 교체지 재생성이 아니다.**
사용자에게는 "새 화면"인데 코드에서는 **같은 컴포넌트의 계속**이다.
그 간극에 남는 state 가 버그가 된다.

**그리고 이 버그는 하필 개인정보 마스킹에서 났다.** 기능의 목적이
"민감 정보를 가린다"인데, 버그의 결과가 **가려야 할 곳을 안 가리는 것**이었다.
기능의 실패 모드가 그 기능의 존재 이유를 정확히 배반하는 형태였고,
그런 기능일수록 **틀렸을 때 눈에 보이는지**를 먼저 확인해야 한다.

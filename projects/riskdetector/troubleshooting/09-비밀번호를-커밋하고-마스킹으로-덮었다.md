# 09. DB 비밀번호를 커밋하고 마스킹으로 덮었다

- **발생**: 2026-04-02 · 커밋 `b0cff41` (덮기) → `7687bed` (추적 해제)
- **증상 한 줄**: 로컬 PostgreSQL 비밀번호가 평문으로 커밋됐고, **다음 커밋에서 덮어도 히스토리에는 남았다**

---

## 현상

`.claude/settings.local.json` 이 저장소에 추적되고 있었다.
그 파일에는 개발 중 허용한 셸 명령이 문자열로 쌓이는데, 그중 하나가 이랬다.

```
"Bash(PGPASSWORD=<평문 비밀번호> /c/Program Files/PostgreSQL/17/bin/psql:*)"
```

**명령줄에 환경변수로 비밀번호를 적었고, 그게 설정 파일에 기록됐고, 그 파일이 커밋됐다.**
공개 저장소다.

## 환경

- Windows 로컬 개발 (`/c/Program Files/PostgreSQL/17/bin/psql`)
- 로컬 개발용 PostgreSQL 17 의 `postgres` 사용자 비밀번호
- `.gitignore` 에 `.claude/` 가 없었다
- 저장소가 public

## 진단

### 1) 무엇이 샜나 — 범위 확인

- **로컬 개발 DB 비밀번호**다. 운영 DB(Render PostgreSQL)의 것이 아니다.
- 접속 대상은 `localhost` 이고, 그 시점 로컬 머신 밖에서는 쓸 수 없다.
- AWS 키 · Google OAuth 시크릿 · JWT 시크릿은 **`.env` 에 있었고 커밋되지 않았다**
  (`backend_core/.gitignore` 와 `.env.example` 이 처음부터 있었다).

즉 **실질 피해는 낮다.** 하지만 두 가지가 남는다 —
같은 비밀번호를 다른 데 썼다면 재사용 위험이고, 그리고 아래 2)번이다.

### 2) 덮어쓰기는 삭제가 아니다 ⚠️

다음 커밋이 값을 `******` 로 바꿨다.

```diff
-      "Bash(PGPASSWORD=<평문> /c/Program Files/PostgreSQL/17/bin/psql:*)",
+      "Bash(PGPASSWORD=****** /c/Program Files/PostgreSQL/17/bin/psql:*)",
```

커밋 메시지는 이렇게 적었다.

> Mask PostgreSQL password in settings.local.json
> Replaced sensitive PostgreSQL password with a placeholder.

**그런데 git 은 이전 커밋의 내용을 그대로 보관한다.**
`git show <이전 커밋>` 한 번이면 원래 값이 나온다. GitHub 에서도 커밋 페이지로 보인다.
**파일을 고친 것이 이력을 고친 것은 아니다.**

### 3) 왜 그 파일이 커밋됐나

`.claude/settings.local.json` 은 이름에 `local` 이 있지만 **git 이 알아서 무시하지 않는다.**
`.gitignore` 에 없으면 추적된다. 그리고 이 파일은
**내가 직접 쓴 게 아니라 도구가 쌓은 파일**이라, 내용이 바뀌는 걸 의식하지 않았다.

## 원인

두 층이다.

**직접 원인**: 비밀번호를 `PGPASSWORD=<값>` 형태로 **명령줄에** 적었다.
그러면 셸 히스토리 · 프로세스 목록 · 도구 로그 어디든 남는다.

**구조 원인**: 도구가 생성하는 파일을 `.gitignore` 에 넣지 않았다.
그 파일의 내용을 **사람이 검토하지 않는다**는 게 문제다 — 자동으로 쌓이니까.

## 해결

같은 날 두 단계로 처리했다.

```
15:05  b0cff41  값을 ****** 로 덮음
15:xx  4418243  .gitignore 에 .claude/ 추가
15:xx  9eac014  .claude 폴더 제거
21:59  7687bed  backend_core/.claude/settings.local.json 추적 해제 (12줄 삭제)
```

`.gitignore` 추가 → 파일 제거 → 추적 해제. **히스토리는 정리하지 않았다.**

**했어야 하는 것**

1. **비밀번호를 바꾼다.** 이게 첫 번째다. 노출된 자격증명은 유효한 동안 노출된 것이다.
   (로컬 DB 라 실제로 바꿨는지 기록이 없다.)
2. 필요하면 `git filter-repo` 나 BFG 로 히스토리에서 제거하고 force push.
   팀 저장소라 **다른 사람의 로컬 이력이 깨지므로** 합의가 필요하다 —
   PR 이 활발히 오가던 시점이라 실제로는 하기 어려웠을 것이다.
3. 애초에 `PGPASSWORD` 를 명령줄에 안 쓴다. `~/.pgpass` 나 `PGPASSFILE` 을 쓰면
   비밀번호가 명령줄·히스토리·설정 파일에 안 남는다.

## 재발 방지

- **도구가 생성하는 로컬 설정은 처음부터 `.gitignore` 에 넣는다.**
  `.claude/` · `.vscode/settings.json` · `.idea/` · `*.local.*` — 내용이 자동으로 쌓이는 파일은
  **내가 검토하지 않는 파일**이고, 그런 파일이 가장 위험하다.
- **시크릿 스캔을 CI 에 붙인다.** `gitleaks` / `trufflehog` / GitHub Secret Scanning 중 하나.
  이 저장소에는 **CI 자체가 없다.** 자동 테스트 1개에 워크플로도 없다.
  혼자 만든 [serverless-uptime-monitor](../../serverless-uptime-monitor/decisions/09-tfsec을-soft-fail로.md) 에는
  ruff · pytest · fmt · tfsec 게이트를 붙였는데, **팀 프로젝트에는 아무것도 없었다.**
- **비밀번호를 명령줄에 쓰지 않는다.** 환경변수 프리픽스(`VAR=값 명령`)는 편한데,
  그 한 줄이 여러 곳에 복사된다.
- **"마스킹했다"를 해결로 기록하지 않는다.** 커밋 메시지가
  *"Replaced sensitive PostgreSQL password with a placeholder"* 인데,
  이건 **해결의 기록이 아니라 노출 지점을 가리키는 표지판**이다.
  히스토리를 뒤지는 사람에게 *"바로 앞 커밋을 보라"* 고 알려 주는 셈이다.

## 배운 점

**git 에서 "고쳤다"와 "없앴다"는 다르다.**
파일의 현재 내용을 바꾸는 것은 쉽고, 이력에서 지우는 것은 어렵다.
그래서 **유출 대응의 1순위는 히스토리 정리가 아니라 자격증명 교체**다.
값을 무효화하면 히스토리에 남은 것은 문자열일 뿐이다.

**그리고 사고를 덮는 커밋은 사고를 표시한다.**
`Mask PostgreSQL password` 라는 커밋 제목은 검색하면 바로 나오고,
그 앞 커밋에 원래 값이 있다는 걸 알려 준다. 조용히 고치는 게 낫다는 말이 아니다 —
**덮는 것으로 끝내지 말고 값을 바꿨어야 한다**는 뜻이다.

**혼자 할 때 붙이던 안전장치를 팀에서는 안 붙였다.**
이 프로젝트에는 CI 도, 시크릿 스캔도, `.gitignore` 사전 점검도 없었다.
"팀이 안 쓰니까"로 넘긴 것들이고, 같은 누락이
[트러블 01](01-Spring이-전시-5일-전에-교체됐다.md) 의 테스트 0개와 같은 뿌리다.

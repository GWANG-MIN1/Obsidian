# Troubleshooting

RiskDetector 에서 실제로 막혔던 것들.
형식과 원칙은 [`../../../infra-lab/troubleshooting/README.md`](../../../infra-lab/troubleshooting/README.md) 와 같다.

```
## 현상       무엇이 어떻게 안 됐는가 (에러 메시지 원문 포함)
## 환경       재현에 필요한 최소 정보
## 진단       가설 → 검증 → 반증의 과정 (막다른 길도 남긴다)
## 원인       왜 그랬는가 (확인한 근거로)
## 해결       실제로 통한 명령·설정
## 재발 방지   다음에 안 겪으려면 무엇을 바꿔야 하는가
## 배운 점
```

## 이 프로젝트에서 특히 남길 만한 것

- **01** 은 코드 버그가 아니다. **두 달 만든 백엔드가 전시 5일 전에 비용 때문에 교체된 사건**이고,
  이 노트 묶음에서 유일하게 *"내가 뭘 잘못 짰나"* 가 아니라
  *"코드로 방어되지 않는 층이 있었다"* 를 적은 것이다.
- **02** 가 기술적으로 가장 밀도가 높다. **실제 환각을 막으려고 8일 동안 범위를 다섯 번 조절한
  기록**이고, 다섯 번 다 그 시점에는 맞는 대응이었는데도 왕복한 이유 —
  **인용 통제와 응답 범위를 한 규칙으로 묶었기 때문** — 이 결론이다.
- **03** 은 가장 예상 못 한 것이다. **버튼 라벨을 짧게 썼더니 모델이 전부 거절했다.**
  LLM 제품에서 UI 문자열이 백엔드 동작을 바꾼다는 걸 그때 처음 봤다.
- **04** 는 남이 고친 버그인데 원인이 **내 계층과의 계약 변경**이라 남겼다.

## 이 저장소의 기록 방식

이 프로젝트는 **실패가 커밋 메시지에 잘 적혀 있다.** 특히 챗봇 커밋(`88f0332`, `8359f35`,
`d379ac4`, `43741c6`, `90f7c68`)은 `문제 / 원인 / 해결 / 영향` 구조로 본문이 길다.
02·03 은 거기서 거의 그대로 복원했다.

반대로 **3~4월 백엔드 커밋은 한 줄짜리**다 (`OCR API 구현`, `CORS설정 추가 + SQL 파일 작성`).
05~09 는 코드와 diff 에서 역추적한 것이고, 그래서 "그때 무슨 가설을 세웠나"가 비어 있다.
**기록이 없는 구간은 복원이 안 된다**는 걸 이 노트를 쓰면서 다시 확인했다.

## 아직 안 쓴 소재

- Upstage OCR 의 정확한 rate limit — 429 를 문자열로 감지하는 코드만 있고 한도는 모른다
- Render 무료 인스턴스 콜드스타트 30초가 만든 문제들 (챗봇 첫 응답, 로그인 폴링, warmup 엔드포인트)
- `localStorage` 로 로그인 사용자 정보를 캐시해 즉시 표시한 것 — 콜드스타트 대응인데 정합성 문제는 안 봄
- PDF 다중 페이지 분할을 프론트(`pdf.js`)로 옮긴 뒤의 좌표계 문제 (남이 작업, 내가 안 따라감)
